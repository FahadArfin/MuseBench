## Behavior and interfaces

- Existing `useChatActions` supplies **Fork chat** / **New side chat** in sidebar and project overview context menus. A compact **Current chat options** button reuses that exact menu. Archived sources omit creation actions; active source fork buttons are disabled. Keyboard navigation skips disabled menu buttons and retains existing Escape/Tab focus behavior.
- All new action payloads include their exact `taskId`. `ResponseActions.onBranch(messageId, taskId)` passes its rendered `chatId`; `App.branchResponse` dispatches that ID and does not read current selection. Successful creation through the shared `act` path exits new-chat/project-overview state into the created chat, closes mobile navigation/modal and focuses the composer. Native returned/thrown errors remain visible through the existing error surface; no fallback is added.
- `ChatRelations.tsx` provides a compact navigable main/fork backlink with current parent title, **Saved conversation** / **Native conversation** context for forks, unavailable-parent text, and expandable recovery information for unresolved native receipts (source/command/child/release identities plus reason). There is no speculative retry or recovery button.
- `projectChatRelations(rows,tasks)` in `sidebar-model.mjs` uses Task 1's `mainChat` helper and returns `{roots,children:Map<string,TaskSummary[]>}`. Only valid side ancestry nests; fork rows stay top-level. Missing/archived/moved parents promote surviving children. Legacy side chains flatten under their usable main. Flat sidebar collection membership/order remains unchanged for drag organization, pinned, recents and search. No task is duplicated within a project list.
- The sidebar disclosure uses existing `MotionDisclosure`, accessible labels/expanded state/controls, blue-accent conventions and reduced motion. Selecting a side reopens its main disclosure. Memo comparison checks all six primitive relation fields and accepts equivalent immutable clones. Nested grids explicitly constrain their columns, fixing visually confirmed left clipping from long names.
- `/side` and `/btw` create fresh linked chats, with optional text stored unsent. `/fork` and `/branch` create history forks. The old copied-context side dialog is removed. Side transcript rendering uses actual messages and does not synthesize the placeholder task request as if it had been sent.
- Preview uses the same action contract/helpers. It constructs each child from the clean task constructor, copying only ordinary mode/run options and the chosen history fields for a fork. It never clones source native identity, usage, goals/drivers, compaction state, queues, leases or receipts. A side has empty messages; a retained fork has a bounded chosen prefix and a sample Saved conversation receipt. Existing parent data/drafts remain separate. Creation performs no simulated send either.
