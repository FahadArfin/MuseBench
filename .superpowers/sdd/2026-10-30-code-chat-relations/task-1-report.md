## Behavior and interfaces

- Action `{type:'createSideChat',taskId:string,text?:string}` validates the exact source, project root and baseline before selection or creation. It creates an empty independent task, with optional unsent text draft. Parent messages, queue, draft, goals, usages, context summaries/capsules, selected attachments, review ownership and native/runtime identity are not copied. Source-from-side resolves a valid main ancestor; orphan/moved/archived/malformed ancestry promotes the source. No send occurs.
- Action `{type:'forkTask',taskId?:string,messageId?:string}` accepts the legacy selected-chat/message form. New controls must always provide taskId. No message means chat-level end. Retained copies preserve the chosen bounded prefix, outcome/truncation markers and old selected-prompt unsent-draft behavior, with a Saved conversation system receipt; no goal/driver/queue/usage is copied.
- Child and TaskSummary persist `chatRelation:{kind:'side'|'fork',parentTaskId,parentTitle,context:'fresh'|'native'|'retained',createdAt,messageId?}` and forks retain `forkedFrom`. Missing parents never cascade-delete children. Restored links are bounded and self/cycle/cross-project/archived parent projection is rejected.
- Shared UI helpers in src/shared/chat-relations.mjs and .d.mts: `restoreChatRelation(value:unknown,taskId?:string):ChatRelation|null`, `relationParent<T extends RelatedChat>(task:T,tasks:T[]):T|null`, `mainChat<T extends RelatedChat>(task:T,tasks:T[]):T`. RelatedChat requires id/projectId and optional archived/chatRelation. relationParent returns the direct navigable parent or null; only side relations should be nested. mainChat follows side ancestry, stopping at a valid main or promoted source. Neither mutates inputs.
- Runtime `forkSession({sessionId:string,lastTurnId?:string,onReceipt?})` returns a NativeForkReceipt or throws with `error.forkReceipt` after submission. Selector routes it to the active adapter; unsupported transports reject. RuntimeState exposes `forkSupported?:boolean` and `forkReceipt?:NativeForkReceipt|null`. Capability is advertised only after verified connection to a durable pinned native host. The runtime checks exact owned session, idle state, config approval and absence of child/compaction/model/turn work; concurrent sends/child starts/compaction are blocked through release.
- Native fork source and returned result are read/validated for root, Meta model/provider, Ask me permission state, inactive work, pending/queued requests and distinct session identity. Provenance must match source, minted command ID and explicit-cut flag. Selected cuts require a completed app-native run mapping and native completed reply; returned native text history must exactly match that source prefix. Source reads are bounded to 4,096 items / 4 MiB. Commands use maxAttempts:1.
- Runtime-owned notification multiplexing is essential: the SDK raw onNotification API replaces one handler. The helper uses an explicit subscribeNotifications callback under the existing runtime route; it never steals the parent stream. Only matching child session + leave command ID + outcome released + cursor admits a child for independent restore.
- Persisted native fork receipts on the source win over stale app-selection snapshots after a crash. Before dispatch the source command ID is saved; returned child identity is saved before validation. Late responses after timeout retain any acquired child ID as unknown without release, reuse or automatic retry. A known boundary/admission rejection is rejected; host internal/transport failures remain unknown.
- Native child uses the distinct saved MSP identity and existing connectNative route. Native history is not injected as app text. Full-access/transport and ordinary tool configuration identities remain exact; workspace/on-demand gateway leases and secrets are never copied. Saved discovery identities require normal fresh review/admission when reconnecting the child. No automatic worktree or file rollback.

## Receipt shape and recovery boundary

NativeForkReceipt is `{sessionId:string,commandId:string,lastTurnId?:string,childSessionId?:string,leaveCommandId?:string,status:'submitting'|'verifying'|'releasing'|'released'|'rejected'|'unknown',at:string,reason?:string,release?:{outcome:'released',viewCursor:string}}`.

Task.forkReceipts holds the bounded last 20 receipts; source records each transition before the next native mutation. A successful child also keeps its release receipt. Restart converts unfinished transitions to unknown. Unknown receipts block further native forks on that source across clicks/restarts, while fresh side creation and normal idle parent usage remain possible. No speculative dismiss/replay/recovery action was added. The prerequisite is external/native inspection of the saved exact command ID and any acquired child session/ownership; the app deliberately cannot certify an unresolved fork by retrying it. Known rejected requests do not permanently block a later deliberate fork.

A selected first user prompt in an MSP source has no preceding completed native cut and is rejected explicitly; retained-history prompt forks retain the old unsent-draft behavior. A completed reply whose native run mapping has aged out of the bounded app journal is also rejected explicitly rather than copying a different context. UI must surface the reason.
