## Contracts and implementation

- `findChatHistory({projectId, taskId, query, cursor?:{messageId,offset}, direction:'next'|'previous'})` is available in the controller, shared bridge types, production preload/IPC and preview bridge. It returns `{hit:null|{messageId,role,offset,length,excerptOffset,excerpt,captureTruncated},coverage,wrapped}`. The excerpt is at most 1,200 UTF-16 characters, query at most 500, and stored body at most the existing 1,048,576 UTF-16 character cap.
- Task/project ownership and existence are validated before reading captured text. Imported library-only copies have no Code project ownership and are explicitly unsupported by this API. Existing imported history/read APIs remain intact. Native MCP read_chat remains unchanged.
- Occurrences are literal, case-insensitive, non-overlapping and ordered by persisted capture sequence and UTF-16 offset. Next begins at the oldest hit, previous at the newest; boundary navigation wraps with `wrapped:true`. Cursor identity includes task, message and an exact occurrence offset for the current query; stale/malformed/foreign cursors reject. Lowercase expansion maps back to original match start/end, so İ and astral prefixes retain correct highlight offsets/lengths.
- SQLite candidates are iterated one body at a time; no full-history renderer load or total scan/count is returned. Previous search retains only the selected candidate rather than allocating an array of every occurrence or generating excerpts repeatedly. The operation remains a synchronous literal scan and can cost more on large captures.
- Existing ChatFind is extended, without a second toolbar. Visible mode preserves DOM ranges spanning formatting, message/occurrence identity, nearest remaining global ordinal fallback and one active highlight. Mutation refresh only rehighlights; explicit query/result navigation alone reveals and releases T301 following. Saved scope uses the existing latest-read queue with complete owner/query/cursor/direction/serial identity, clears stale rendered results immediately while pending, and never retries a stale cursor automatically.
- The compact saved reader uses React text nodes and one mark, reports capture/source/offset and coverage, and preserves task state. Browser sample, legacy capture and truncation labels remain honest. Ctrl+F/Escape/Enter/Shift+Enter and web search remain in the existing controls.

## Limits and outstanding integration gates

Captured text can omit material unseen by the app or discarded before migration and stops at the existing per-message cap. Matches are over literal stored text; formatted Visible search remains its own DOM scope. Saved search rejects a stale cursor after edits rather than silently jumping; a fresh query recovers. It does not search imported library-only copies or connect to a provider. Full combined suite, independent review, remote CI, release packaging, hash validation and final installed UI are owned by the parent workflow and not claimed here.
