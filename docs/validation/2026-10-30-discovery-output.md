# CS02 useful discovery output validation — 30 October 2026

This source change preserves the existing native Muse backend and original discovery result/schema validation. It adds text-only lossy previews after validation, with source/tool/catalog identity and completed/failed outcome, a 16,000-code-point ceiling including the omission marker, explicit omitted-code-point/non-text-block counts, and the original fully encoded frame size in bytes. The request-ID reserve covers the maximum admitted encoded ID (128 UTF-16 code units at up to six JSON bytes per unit, plus quotes), and includes the emitted JSONL newline. `preview.originalWireBytes` is the original nested frame size with this conservative reserve, not an observed network count. Fully encoded responses remain at most 131,072 bytes; transport receive budgets were not expanded.

Small results retain the complete original wire shape. Oversized output omits media, metadata and structured content, never publishes partial `structuredContent`, and explains when no eligible text exists. A source-provided `truncated:true` is separately attributed in the notice. Invalid original structured content remains unknown, closes the source and is not retried.

## Review fix: all admitted request IDs

Independent review reproduced a whole-frame overflow with the earlier ASCII-only ID reserve: a result measured at 131,072 bytes required 131,200 emitted bytes for an admitted ID of 128 backslashes. The protocol therefore replaced the source/outcome receipt with its generic overflow message. The controller ruled that worst-case encoded size for all admitted IDs supersedes the plan's previous ASCII placeholder, without increasing receive budgets. The plan and task brief now state this ruling explicitly.
