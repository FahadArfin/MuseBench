# T306 native retry observations

The installed, pinned `@muse-code/sdk@1.4.14` declarations (`dist/src/msp.d.ts`, `TurnModelRetryScheduledParams` and `TurnRetryScheduledParams`) describe nonterminal `turn/modelRetryScheduled` and `turn/retryScheduled` events. They report a scheduled backoff duration, not an absolute fire time. MuseBench now observes both through the existing exclusive-session, current-turn, cursor-deduplication and bounded-event gates. Retry provenance must identify the owning session stream and one durable source record. Foreign sessions remain ignored; unexpected turns and conflicting cursors retain their existing stop behavior. Malformed retry counts/delay/provenance fail closed.

One current observation retains only kind, failed attempt, scheduled next attempt, maximum attempts and delay. Counts and delay are safe integers; no provider system, kind, reason or raw error text enters the projected status. The per-turn duplicate map now retains hashes, matching the existing session-wide hash evidence, rather than retaining raw payload strings. Native message/tool/compaction progress, terminal state, disconnect and new submissions clear the observation. Duplicate replay cannot restore a cleared notice; callbacks from a replaced connection cannot publish it.

The shared Code renderer reports that **Muse scheduled a retry**, with attempt counts, recorded delay and “Remaining delay unknown.” It has a polite atomic accessible status, wraps on narrow layouts and adds no motion. There is no timer, scheduler, resubmit, command ID mint, queue admission or terminal reclassification. Existing work and permission gates remain authoritative.
