# CS04 bounded renderer delivery — 30 October 2026

Code presentation now holds at most one in-flight pushed snapshot and one replaceable newest pending snapshot. Existing controller 40 ms runtime coalescing, persistence, notifications, Work/Sites/Spaces observers, native sessions and background ownership are independent. An acknowledgement means the renderer's state consumer accepted or superseded that presentation; it never authorizes or completes an action/model/native navigation operation.

The private version-1 envelope contains generation, revision and canonical state. Main validates acknowledgements against the current trusted main frame and exact in-flight generation/revision. Reload, renderer loss, detach and close invalidate ownership. After two seconds without consumption, push delivery suspends without resending; a matching acknowledgement or reattach reads current canonical state. The acknowledgement path also checks elapsed time when a timeout callback is overdue. Diagnostics contain only ownership, counts and timing, with no state payload or provider data.

The preload has one ordering gate for pushes, initial reads and every Code dispatch response. Subscribe occurs before the initial read. A stale push following a newer invoked read is discarded and its exact delivery acknowledged, so it cannot roll back the view or leave the stream blocked. A fresh attach always reads canonical state. The public API remains state-only: `getState(): Promise<AppState>`, `dispatch(): Promise<AppState>`, `onState(AppState)`, and `chooseProject(): Promise<string|null>`.

Controller clarification: bounded 1+1 ownership applies to the push stream, not all IPC traffic. Invoked reads use `publisher.read()` and the same revision clock without waiting for push consumption. Private command replies carry a fresh canonical snapshot and the unchanged original action result, which may contain a second full state. Captured action data is never relabeled as canonical at a newer revision. App accepts canonical updates only through the state subscription (with a guarded preview bootstrap fallback), preserves original command errors/receipts, and suppresses late result-driven navigation/draft changes after the selection or shell destination changes. Choose-project returns only a path/null and produces no Code state snapshot.
