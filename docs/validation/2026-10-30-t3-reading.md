# T301 reading continuity — 30 October 2026

The Code transcript now remembers up to 100 project/chat reading positions in memory. Returning to a reading chat restores a stable message anchor and its viewport offset before paint, falling back to a clamped scroll offset when that message is no longer retained. The cache stores position and follow intent only; it never supplies another chat's messages or persists transcript data.

Upward wheel, keyboard and touch input release following immediately. The old 100px bottom band no longer decides follow intent. Jump to latest explicitly re-arms it. The existing transcript reference stays in App, with a focusable Conversation viewport for keyboard scrolling. Find, prompt timeline and Sub-Agents navigation release following before moving the viewport.

Restoration can correct real layout changes for 1,200ms, then stops correcting. New transcript input, explicit navigation and chat changes cancel pending correction. Mutation/resize observers keep an armed transcript at the latest content, without depending on cloned message/shell-result arrays. All scrolling owned by this hook is instant, including reduced-motion layouts. Browser clamping after a viewport resize does not release following at the bottom.

## Limits

Positions expire on app restart or cache eviction. Correction is deliberately bounded; images/layout changes after its deadline can move a released reading viewport. Touch behavior has event handling but no physical touch-device acceptance claim. Existing visible find still rebuilds/recenters on mutation; T302 owns occurrence stability and explicit-only find reveals, using this hook's `releaseForNavigation` interface. No native model acceptance, application-wide performance gain, remote CI, release/install or installed UI acceptance is claimed. Full baseline tests are reserved for final combined CI under the task's scoped validation instructions.
