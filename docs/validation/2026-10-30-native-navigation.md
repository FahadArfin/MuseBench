# CS03 native navigation completion — 30 October 2026

Navigation now returns the existing shell inspection with optional `navigation: {committed: true, visualSettled: boolean}`. A fresh request token must be acknowledged by a React layout commit matching the exact requested shell destination. Settings/Customize validate the actual selected category/tab; Code includes selected chat/project identity. Already-selected destinations still require a new token. Changing the destination during optional visual observation rejects the result.

The eight-second deadline is rechecked in main when replies arrive, even if its timer callback is overdue. Main requires ordered claim/commit/visual phases bound to the pending token and requested target/section. Cancellation or renderer loss has one terminal result, clears ownership and prevents late replies or replay. Screenshots retain their independent pixel/visibility/cancellation contract.

Visual observation is at most 400 ms, uses no requestAnimationFrame dependency, and considers only visible finite running destination transitions. Unrelated controls/surfaces, hidden/offscreen surfaces, infinite animations, paused animations and zero playback rate do not block completion. A delayed transition can return a committed destination with `visualSettled: false`, even before visible headings appear. This is shell evidence, not provider-page readiness or a screenshot guarantee.

Diagnostics retain the last 20 dispatched shell operations with allowlisted operation/target, latest phase/outcome, measured elapsed milliseconds and at most five phase observations. No request tokens, sections, chat IDs, project IDs, text, paths, URLs, arguments, credentials or provider content are retained in those receipts. Earlier diagnostic health/event fields are preserved.
