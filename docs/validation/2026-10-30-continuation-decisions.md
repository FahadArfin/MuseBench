# Remaining roadmap continuation decisions

These decisions accompany the native child-control verification, recent local excerpts and on-demand tool discovery continuation. Exact feature and release evidence remains in the linked validation reports. Earlier decisions that were superseded are retained here as history.

## Native child-control verification

1. Parent owns independent whole-feature review. Author completion alone is not release approval; the extra review costs time but tests a separate reading of the contract.
2. The new runner is an opt-in acceptance test, not a production behavior change. It must fail when required native settlement is missing. If its assumptions are too narrow, a supported host behavior could need a revised test rather than a product change.
3. Keep the branch, worktree and evidence until parent integration. No implementer push or installation. The cost is retained local storage.

## Recent local excerpts

1. One implementer owns the connected controller/UI/queue task; the parent independently reviews it. Splitting these coupled boundaries further could obscure ownership errors; the cost is less implementation parallelism.
2. When capsules exist, source records, outcomes, native session and project ownership restore from the authoritative task row. This prevents an older selected snapshot from reviving changed source evidence. If wrong, the changed restoration precedence could affect local recovery for capsule-bearing chats.
3. After a late proven rejection, recovered excerpts stay prepared but unstaged when a newer unrelated draft exists. This protects the new request; the cost is one explicit Include action to reuse the old review.
4. The focused smoke can use the exact installed executable, with disposable state and external networking blocked. This establishes installed UI behavior only; real provider acceptance still needs its own evidence.
5. Readable You/Muse messages are the default review; exact serialization is collapsed. If wrong, presentation can be revised without changing the reviewed payload or send behavior.

## On-demand MCP tools

1. Limit wrapping to explicitly reviewed, disabled global stdio sources. The pinned host cannot safely replace enabled direct definitions. Other connection types retain their existing direct path; the cost is a smaller initial source set.
2. One implementer owns source inspection, consent, gateway, runtime and restoration. The cost is a larger integrated review if a boundary needs rework.
3. Existing user authorization covers implementation, feature commits, review, integration and push. No repeated design gate is added; these changes remain reversible.
4. Superseded: the initial absolute-command-only, explicit-framing-only and blanket plugin exclusion proved too restrictive. Current behavior binds bare native executables to exact PATH resolution and identity, permits bounded automatic JSONL initialization and inspects known package-bound plugin MCP names. Unknown declarations, shell scripts and incompatible framing remain excluded. If these checks are too strict, a source needs a later supported path rather than silent rewriting.
5. Validate only a bounded local JSON Schema subset, outside Electron's main loop. References, regex, formats and other unsupported keywords are rejected explicitly. The cost is that complex tools may be excluded from the discovered catalog.
6. Superseded: an initial one-hour duplex process lifetime would stop healthy long connections. Duplex Jobs now live with their owning pipe, with finite startup, call, output and cleanup bounds. Default command execution keeps its existing limit. Long sessions retain owned processes until disconnect; owner-death cleanup must remain reliable.
7. Native shutdown can kill a wrapper before it sends cleanup evidence. The app therefore owns a supervised worker through an authenticated loopback broker, with independent unpredictable tokens and shutdown revocation. The additional process and lifetime protocol cost complexity, covered by wrapper, worker, owner-death and revocation checks.
8. An authenticated lifetime pipe revokes the worker on idle native-wrapper EOF, before a later controller disconnect. Losing a submitted effect remains an unknown outcome and is not replayed. This adds a connection-lifetime dependency; a broken pipe stops owned tools instead of leaving them running.
9. Independent review's transport, schema-ordering and integrated-fixture findings are defects within the agreed scope. Their fixes must preserve explicit unconfirmed cleanup, bounded schemas and saved-session identity. The cost is another focused verification pass before release.

## Review boundaries retained

Real-model selection and quality, POSIX runtime behavior, personal live tool collections, unsupported source types, and native deferred registration have separate prerequisites. The release owner verifies publication, installation and exact packaged behavior after code review. Ordinary source revision checks are not a claim to eliminate every adversarial same-account filesystem race. These exclusions do not authorize fallback inference, permission changes or simulated provider acceptance.

No decision enables inference during idle time, grants execution to imported content, changes personal permissions, or treats a fixture as live provider acceptance.
