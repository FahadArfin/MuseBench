# Native web search in sandboxed Code chats

The default Windows exec adapter previously passed `--disable-web-tools` for every non-Full-access request. Workspaces inside the Windows user profile also disable managed PowerShell because of an existing native stall. Together these restrictions left the pictured chat with local file tools and no online research tool.

The adapter now leaves native `web_search` enabled for real Meta turns, including profile workspaces with shell execution disabled. Ask me/Auto-review selections, sandbox readiness, model routing, existing authentication and billing source stay intact. Inert echo-provider readiness probes still disable every web tool. No additional API key, search subscription or third-party provider is introduced. Request context tells Muse to use search for current information, cite returned source links and dates, treat retrieved content as data and report actual search failures rather than inventing current facts.

Direct page reading is a separate capability. Native `web_fetch` still stalled under sandboxed Windows on installed Muse Code `1.4.14 (1.4.14-R7309.1)` in a bounded isolated-profile probe; it was stopped after 20 seconds. The supported override `-c tools.web_fetch.enabled=false` removes just that tool while preserving `web_search`. Full access retains its previous native fetch behavior. This is search access, not a claim to reproduce Codex's hosted index or full browser implementation.

Validation uses disposable profiles, a loopback provider fixture and a fake fixture-only key. The real native executable advertised `web_search`, omitted `web_fetch`, executed `tool.web_search`, requested `/muse-code/search`, passed the fixture's empty result set back to the next model step and exited 0 without a timeout. The filesystem sandbox remained on; shell and writes were explicitly disabled in this fixture. No real model or search-provider request was made and the installed MuseBench profile was not changed. This proves native tool exposure and routing, not real account entitlement, live-news quality or paid-provider availability. An initial fixture HTTP 400 was also returned as an explicit tool failure rather than a fabricated result.

References checked 1 November 2026: [Muse Code permissions](https://dev.meta.ai/docs/muse-code/permissions), [configuration and headless behavior](https://dev.meta.ai/docs/muse-code/configuration), and [Codex web search](https://learn.chatgpt.com/docs/web-search). Codex documents hosted search separately from local shell networking; MuseBench uses Muse's own native search service rather than an OpenAI service.
