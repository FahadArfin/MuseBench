# T302 captured-history find — 30 October 2026

The existing Ctrl+F chat search now offers Visible and Saved history scopes. Visible preserves formatted text and cross-node DOM ranges. Streaming rebuilds ranges while retaining the selected message and occurrence; if that occurrence disappears, the nearest remaining ordinal becomes active without scrolling. Query changes and explicit next/previous reveal results through T301's releaseForNavigation. Highlight refresh alone never releases following or recenters the transcript.

Saved history uses the project-owned Code task capture. A next/previous request returns one occurrence with original UTF-16 offset and match length, up to 1,200 characters of safe plain-text excerpt, capture coverage and an explicit wrapped flag. It finds repeated occurrences, evicted messages and text beyond the first 12,000-character reader page. The saved reader renders exactly one mark and does not load history into App or invent total counts. It distinguishes app-received, retained-legacy and preview samples, and flags a truncated message capture. Imported library copies keep their existing reader; they are not project-owned Code tasks and are outside this API.

The controller verifies the task belongs to the supplied existing project. Invalid directions, queries over 500 UTF-16 characters and malformed, foreign or stale occurrence cursors fail. The store streams SQLite candidate bodies one at a time, preserving its existing 1,048,576 UTF-16 character capture cap, and never performs a total-count query for find. Literal matching preserves original offsets even when Unicode lowercasing expands a character. The API performs no provider, draft, task-selection or transcript mutation. A large capture can still require a synchronous scan; this is bounded delivery, not a constant-time or background search claim.

## Review corrections

Independent review found two missing guarantees. ChatFind now accepts a saved result only after a successful current read, so rejected queries and stale cursors cannot restore the previous same-owner reader/mark, enable stepping or trigger its navigation effect. The store searches the cursor message and its indexed direction range before considering a separate wrap range, avoiding scans through messages already passed.

The new scan-count regression failed against the prior implementation (all three 4,096-character fixture bodies scanned during a same-message step) and now passes all six next/previous/cross-message/wrap cases. The amended search smoke also reproduced both rejected-query and real stale-cursor failures before the fix, then passed with zero readers/marks and disabled controls on error, plus recovery on a fresh successful query. Final reports: `artifacts/chat-history-find/preview-mVAj3K/report.json` (10 checks), `artifacts/chat-history-find/desktop-t8vHCB/report.json` (9 checks), no renderer errors and zero counted provider admissions. The focused history/latest-read tests passed 23/23; TypeScript/production build and diff checks passed. Existing Vite chunk advisory and cold/no-match synchronous scan limitations remain. Broad unchanged suites were not repeated for this correction.
