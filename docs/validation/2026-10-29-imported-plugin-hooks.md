# Imported plugin hook controls

Verified with Muse CLI/SDK 1.4.14 on Windows, 29 October 2026. This extends the [native plugin hook controls](../VALIDATION-native-plugin-hooks.md).

Customize can review and approve supported command hooks from Claude- and Codex-compatible installed plugins. The same compact Tools & hooks section shows the complete shell command, source file, event matcher, timeout and foreground/background behavior. If an imported `silent` setting is present, the review explains that Muse ignores it. Each hook has its own exact approval and revocation; installation or inspection never executes it. Desktop and preview share these controls; preview actions are simulated.

## Source binding

MuseBench reconciles the native projection with one contained, bounded installed source handler. Supported layouts are inline manifest hooks, conventional `hooks/hooks.json`, and explicitly selected JSON files. Claude's PreUserTurn alias is reconciled with UserPromptSubmit. Unknown fields, ambiguous matches, conditions, missing/escaped files or mismatched event/command/matcher/timeout/async fields cannot receive app approval. Timeouts are limited to 1–600 seconds. Shell strings retain all syntax, including line breaks; recognized embedded credentials cause refusal instead of hiding executable code or exposing their values.

The app keeps its own complete package fingerprint, native definition/approval and settings identity. Two native differences were observed and tested:

- Persisted foreign records use `claude`/`codex`, while public inspection uses `claude-compatible`/`codex-compatible`. Public records omit internal agent-parser and compatibility metadata. Those fields remain in the app's inventory fingerprint even though they are excluded from the public projection comparison.
- Foreign hook `source_digest` differed from the recorded package digest. Editing an installed skill file left native `valid` true and its hook definition hashes unchanged in all three fixtures. MuseBench therefore treats that field as opaque native identity for source-verified imported hooks and independently hashes every package file. A real post-approval edit was rejected by the production configuration check and prevented a host from starting. Restoring the exact bytes restored the earlier fingerprint. Native hook and MCP digest checks retain their existing stricter comparison.

No third-party command, real profile or account credential was used for these tests. Package files were restored in `finally` blocks; audit folders were retained.

## Native acceptance

Three generated bundles covered conventional Claude, inline Claude and explicit-file Codex hooks. The production Customize service inspected and reviewed them, issued exact official approve/reject commands and checked stored app grants. Runtime connections used the normal configuration and permission checks. The actual provider was verified to be local `echo` before each direct SDK turn; zero model requests were made.

| State | Owned recorder events | Completed live hook receipts |
| --- | ---: | ---: |
| No approval | 0 | 0 |
| One prompt hook approved | 1 | 1 |
| All ten supported hooks approved | 9 | 6 |
| Revoked and reconnected | 0 | 0 |

The nine events were SessionStart, UserPromptSubmit and Stop for each bundle. Live prompt/stop receipts totaled six; startup execution was proved by owned recorder output, not a claimed missing notification. The Codex PreToolUse hook was approved but no tool call was generated by echo. Separate explicit manual hook tests proved matcher inclusion for Bash and exclusion for Write. All four owned hosts and recorder processes exited. Removing an app grant while native approval remained enabled prevented host startup.

This runtime-owned connection test uses a direct SDK echo turn to avoid MuseBench's Meta-only model selector. It does not claim normal Meta chat submission or live stale-connection refusal; those are distinct from the separately covered configuration/reconnect regressions.

## Limits

- Conditional imported `if` hooks remain setup-required. The native manual test did not enforce the tested condition, so it does not establish normal-runtime conditional execution.
- An earlier owned Windows fixture with a quoted absolute script path failed in the native shell host. Unquoted fixture paths without spaces worked. MuseBench preserves commands rather than rewriting their shell syntax; approval does not prove that arbitrary imported commands or dependencies work on this OS.
- Unknown events/behavior, additional output-capability selection, custom XDG plugin stores and arbitrary managed sources remain outside this feature. A foreign bundle whose other capabilities cannot be verified may still need the official CLI.
- Native macOS/Linux execution, real provider inference and third-party integrations are not implied by Windows echo or synthetic UI evidence.

## Validation

- 1,356 local tests passed, including 94 focused hook/capability tests.
- Production TypeScript/Vite build passed.
- Thirteen plugin-control checks passed in browser and Electron, including exact shell consent, independent revoke, unsupported controls, stable idle inspection, late-result handling and narrow layout. The narrow screenshots were visually inspected.
- Final review identified whitespace loss in the last approval screen. A separate command block now preserves newlines, shell comment boundaries and repeated quoted spaces, while wrapping long lines. The regression failed in both renderers before the fix and passed afterward; the complete 1,356-test suite and 97-scene renderer parity check passed after the fix. No second review was used.
- Catalog preview/desktop checks passed, including shared Installed rows, full-source search, retained filters and continuous 240-row fixture scrolling.
- Shared renderer parity and immutable release/installed acceptance are recorded separately in the delivery receipt.

Local evidence is retained under ignored `artifacts/imported-plugin-hooks/`: projection, execution, matcher, integrity and production service reports, test/build logs. UI screenshots and checks are under `artifacts/plugin-tools-ui/`.
