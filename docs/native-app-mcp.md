# Native app control

MuseBench ships a local MCP server for Codex and other stdio MCP clients. It inspects and navigates the actual open desktop app without mouse coordinates, Windows automation or Electron remote debugging.

1. Open **Settings → App control → Turn on**.
2. Copy the displayed MCP configuration into your client's stdio-server settings. Electron provides Node; a separate Node installation is not required. On Windows, MuseBench prepares a private runtime and bundled server outside its installation folder, so an idle client does not hold desktop update files open.
3. For Codex, use `codex mcp add musebench --env ELECTRON_RUN_AS_NODE=1 --env NODE_OPTIONS= --env NODE_PATH= -- <command> <args...>` with the command and arguments displayed in MuseBench. Quote each path for your shell. Codex documents this configuration at https://learn.chatgpt.com/docs/extend/mcp?surface=cli.
4. Reload MCP servers in the client, or start a fresh client session. Call `app_status`, then `inspect_ui`.

The available tools are `app_status`, `inspect_ui`, `navigate`, `screenshot`, `diagnostics` and `read_chat`. `navigate` accepts named destinations and optional Settings/Customize sections; inspect its schema for the current list. Navigation acknowledges an exact committed shell destination, including the selected Settings category, Customize tab or current Code chat/project identity. Each call has a fresh request token, even when its destination is already selected. Remote services may still be loading: `app_status` reports that separately. Screenshots show currently visible app content. Chat history is local Muse Code history, selected by ID, bounded to 30 messages per call and 3,000 characters per message.

Navigation preserves the inspection fields (`source`, `viewport`, `theme`, `headings`, `controls`) and adds `navigation: {committed: true, visualSettled: boolean}`. A React layout commit must match the registered request and destination before this metadata can be returned. The optional visual observation lasts at most 400 ms and considers visible finite running transitions on the destination and its navigation surfaces; unrelated controls, hidden/offscreen surfaces, infinite animations and paused/zero-rate animations do not hold it open. It uses no animation-frame callback. A delayed transition can therefore return `committed: true, visualSettled: false`, with headings still absent until their pixels become visible. Use a separate screenshot for pixel evidence. Personal search/feed/library calls acknowledge the app shell after the existing service command returns; they do not verify the embedded provider's requested page, login state or content.

The existing eight-second request deadline is checked again by the main process when a reply arrives, including when the timeout callback is overdue. Cancellation, expiry, reload or renderer loss prevents late replies; no navigation is retried. A destination changed during visual observation is rejected rather than returning a snapshot for a different selection.

`diagnostics.operations` contains at most the last 20 dispatched shell operations. Each receipt contains only allowlisted `operation`, `target`, latest `phase`, `outcome`, measured `elapsedMs`, and up to five `{phase, elapsedMs}` observations. Phases are `dispatched`, `claimed`, `committed`, `visual-settled`/`visual-unsettled`, and `replied`; outcomes are `pending`, `completed`, `failed`, `cancelled`, `expired`, or `renderer-lost`. The last phase remains available on failure. Receipts omit request tokens, sections, chat/project IDs, text, paths, URLs, arguments and credentials. Existing health/event fields remain available. The earlier personal-app timeout remains unexplained; a fresh receipt is needed to identify which phase did not finish.

For maintainers: `createNativeRenderer(...).call(operation, args, signal)` and public tool names remain unchanged. The private bridge adds `musebench:native-phase` and `musebench:native-cancel`; main validates the current trusted sender, pending token, requested target/section, ordered claim/commit/visual phases and deadline. `useNativeControl` registers the expected shell state, then its layout effect acknowledges the fresh token only when committed state and actual selected modal controls agree. Future state-delivery changes must preserve that ordering and must not acknowledge navigation merely from an incoming state envelope.

Enabling persists over restarts. Access tokens are private to the OS user, rotate at each startup, and are removed on clean shutdown. The server listens only on IPv4 loopback, rejects browser-origin requests, and exposes a fixed action schema. No tokens appear in the copyable configuration. Turn App control off to revoke access immediately. Clients reconnect on each tool call; requests are never automatically replayed. While the desktop is closed, tools return an unavailable result. Reopen the app and make a new request.

Windows clients configured before the cached runtime was introduced must copy the new configuration once, close the old MCP connection and reconnect. Existing grants do not change. The cache is under the profile's `native-control/runtimes` and `native-control/bridges` folders, addressed by file content. Runtime, ICU data, V8 snapshots, notices and server bytes are verified before the configuration is returned. Running cache versions are never overwritten or automatically deleted. A new bridge reuses an unchanged runtime; older clients keep their original schema until their configuration is refreshed. A damaged or linked cache is refused. For a repeated cache-integrity failure, close MCP clients before removing only the affected cache version and refreshing App control; never remove the profile, settings or session data. These cached runtime files consume local disk space but do not add a second executable to the download.

Windows Store hosts can redirect a regular profile child into their private LocalCache without creating a symbolic link. MuseBench verifies the directory's filesystem identity and uses its canonical location for both the cache and connection descriptor. It does not move the profile or reset sessions. Actual symbolic links, junctions and hard-linked files remain refused.

On other platforms, the configuration still uses the installed executable. If it is moved, copy its configuration again. AppImage mount paths can change; use the installed `.deb` for a persistent Linux MCP configuration.

The tools do not execute arbitrary JavaScript, run shell commands, send provider messages, change approvals, install extensions or handle purchases. Provider login pages, OS dialogs and embedded remote-page controls still need their supported integration or direct user interaction. Shell inspection excludes embedded pages and input values. Diagnostic events record failure types and times, not console messages or URLs.

Preview uses the same UI components but simulates the connection switch. Validate a real connection with `node scripts/native-control-smoke.mjs`. Its Windows lifecycle check keeps a cached MCP process alive while replacing disposable source files, verifies the unavailable result while the host is closed, and then reconnects to a reopened host without replay. This uses a fixture app service; the separate native and packaged checks inspect actual rendered app controls. Routine releases validate Windows x64; deferred platform builds run package checks when explicitly requested. These tests use isolated profiles and make no model requests.

Screenshots require an open, restored MuseBench window. Hidden or minimized windows return an actionable error without bringing the app to the foreground. Hiding, closing or reloading the app during capture discards the image; cancelled requests cannot return late pixels. Capture has a six-second deadline and only one native capture can be outstanding. Electron has no capture cancellation API, so an underlying capture that has not settled continues to block new captures after the client deadline. The native smoke check verifies actual image pixels, hidden/minimized rejection and recovery after restoring the window.

On Windows with Electron 45, an isolated reproduction captured the previous red frame after minimizing and changing the page to green; a second capture returned green. A fully hidden capture instead timed out. Visible and covered-window probes did not reproduce stale frames. These findings establish the visibility guard's scope, not a universal guarantee that every animation has finished. Use `inspect_ui` to check selected controls and loading state alongside screenshots.

Native cleanup retains its original WebContents references, so closing the window can remove listeners after Electron destroys the BrowserWindow. The smoke test closes the real window and requires normal process exit; calling `app.close()` alone does not test this shutdown order.

`node scripts/native-navigation-smoke.mjs` runs the shared production hook in a disposable browser fixture, including wrong section/chat commits, unrelated renders, stalled animation frames and cancellation. It is registered alongside the public MCP smoke in the existing native CI suite. Set `MUSEBENCH_EXECUTABLE` to an exact packaged executable when running `scripts/native-control-smoke.mjs` to exercise that binary with a new isolated profile; omitting it checks the local source build. Neither mode modifies an existing profile or makes a model request.
