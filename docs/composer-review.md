# Composer review

Self-review, 25 October 2026. No independent agent review was performed.

- The compact input, plus menu, approval chip, effort picker, microphone and circular Send control follow the supplied screenshots. Dark/light and narrow screenshots were inspected. Existing project overviews, nested chats, review controls, drafts, keyboard shortcuts and theme preferences still pass their packaged regressions.
- Settings use shared finite validation at IPC, controller and runtime boundaries. Unknown values/fields are rejected. Each task stores its settings; older tasks get High/Ask defaults and a new chat resets to those defaults. A controller test verifies disk persistence, exact native arguments and rejection of settings changes during a run.
- Reasoning maps to the real --reasoning-effort flag on Meta requests. Echo probes omit it because the installed provider rejects that flag. Ask and Auto-review use the documented built-in profiles; No prompts uses --approval-mode never --approval-judge off. None introduces a sandbox bypass, unrestricted profile, trust grant, arbitrary native argument, external tool, or hook.
- Readiness is checked again before each request. Native process ownership, stop behavior, command evidence, explicit plan approval and independent preview/check/checkpoint gates remain enforced. An actual packaged Extra high/Auto-review request passed exact file edits, a managed sandboxed PowerShell test, preview, app check, acceptance, persistence and confirmed native cleanup.
- Speech uses a fixed packaged helper and narrow status/start/stop/cancel IPC limited to the trusted main renderer. Remote pages retain no bridge and no browser microphone permission. Starting requires a focused app. Navigation, overlays, blur, product switching and app shutdown cancel capture. Only final text reaches the draft; no recording is stored and no message is auto-sent.
- The helper watches the parent process and bounds recording to 90 seconds. The service rejects concurrent capture, retains ownership until close, bounds output, decodes split UTF-8, and drops late output after cancellation. Two cancellation/stop race tests first reproduced retained or late text and now pass; cancellation remains authoritative regardless of stop order. A cancelled pending availability probe cannot later open the mic.
- The UI recognition test synthesizes a disposable WAV, swaps only the helper device argument at the test process boundary, and runs the real compiled Windows recognizer, IPC and draft updates. The fixture is never used by the product and no test injection switch is exposed in IPC. A missing WAV exercises the native error path and retains the draft. The physical default microphone and recognition accuracy for this user's voice remain untested.
- The packaged source/build files and both native helpers match source bytes. The normal saved-profile check confirms existing history, signed-in collections and enabled sandbox/context isolation/web security. It records only fixed check descriptions and booleans; no account text, URLs, credentials or screenshots are saved.

Limitations: Windows dictation requires an installed recognition language, an accessible default microphone and the operating system's microphone access setting. The recognizer is local System.Speech, not Muse's unsupported-on-Windows voice feature. Recognition is editable and may be imperfect. Non-Windows SDK connections reject nondefault composer options instead of silently ignoring them. The Muse model remains the CLI's configured model. The Windows exec transport cannot answer human approval prompts; unresolved requests stop. Existing profile-folder command restrictions remain in force.
