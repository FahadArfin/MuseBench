# Review a reply's changes

Use **Review changes from this reply** beside a Muse Code response. The dialog shows source changes observed during that run. Expand or collapse files, open them in your editor, and mark them reviewed. Refresh to check whether current workspace files still match the capture. A later edit makes that file stale and unreviewed.

Choose **Comment**, select Before or After and the line range, then write your feedback. **Add to draft** appends the file/run/line reference and your note to the current composer. Existing text, attachments and message mode stay intact. You can edit the result and send it when ready; adding feedback never calls Muse.

Captures describe observed workspace edits, including edits that another tool or person may have made. They are not a guarantee that Muse authored every change. Old replies, uncertain or interrupted runs and failed snapshots may have no capture. These states are labelled explicitly. Binary/large files and excess files show their capture limits instead of an invented text comparison.

Captures stay on this device: up to 20 runs per chat and 100 overall, with 100 changed files and 1 MiB of diff text per run. Existing source exclusions apply. Deleting a chat deletes its captures. This feature does not restore files, rewind native history or change permissions; existing checkpoints remain available for files-only restoration.
