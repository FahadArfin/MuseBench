# T3 Code recommendations for MuseBench

Reviewed source snapshot: [`pingdotgg/t3code@e9a11d4`](https://github.com/pingdotgg/t3code/tree/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa). MuseBench baseline: `0f83414`. User explicitly chose to keep Muse as the backend.

T3 controls separately authenticated coding agents; it does not share one provider subscription across models. Its own Muse adapter uses the native SDK. The useful additions here are small workflow mechanisms, not a new provider stack.

| Selected | Benefit | Evidence |
|---|---|---|
| T301 Reading continuity | Return to the same passage after switching chats; upward scrolling pauses following immediately | [Responsiveness study](t3-performance-2026-10-30.md) |
| T302 Captured-history find | Extend current Ctrl+F beyond the rendered window; preserve current match during streaming | [Responsiveness study](t3-performance-2026-10-30.md) |
| T303 Saved prompts | Park several unsent drafts and recover them without using an executable queue | [Workflow study](t3-workflow-2026-10-30.md) |
| T304 Quote response | Put an exact passage in an editable draft with source attribution | [Workflow study](t3-workflow-2026-10-30.md), [Muse study](t3-muse-2026-10-30.md) |
| T305 Keyboard navigation | Move between workspace areas and chat rows with fewer keystrokes | [Workflow study](t3-workflow-2026-10-30.md) |
| T306 Native retry status | Explain a provider-owned wait without adding automatic resubmissions | [Muse study](t3-muse-2026-10-30.md) |
| T307 Measured transcript containment | Reduce redundant rendering while typing if fixed-fixture evidence supports it | [Responsiveness study](t3-performance-2026-10-30.md) |

Already present: persistent sessions, forks, linked side chats, worktrees, queues/steering, compaction, child controls, bounded history, durable current drafts, source excerpts, review feedback, project actions, schedules, activity inbox, native MCP and reviewed integration catalogs. These are not counted as new T3 features.

Not selected: additional providers, rich editor, generic/question attachments, automatic native replacement/continuation, generalized inline context records, Git-host publication controls, auto-resume/cleanup and snooze taxonomy. Reasons and prerequisites are in the detailed studies and [design](../superpowers/specs/2026-10-30-t3-workflows-design.md). These are research options, not a claim that every capability can be safely ported unchanged.

The source was inspected without executing upstream code or making model requests. Implementation, local fixtures, exact CI, installation and live provider acceptance are tracked separately in the roadmap and validation evidence.
