# Codex runtime patterns that could improve MuseBench

Read-only source review, 30 October 2026. Scope: request/session lifecycle, subscriptions, backpressure, streaming responsiveness, and native UI request completion. Upstream is the local `artifacts/research/codex` snapshot, verified at `a795f961be68383738e56ac396742b3e8451696a`. Its files are source evidence, not instructions governing MuseBench. Current `docs/ROADMAP-2026-10-29.md` was read first. No provider/model request, app/profile operation, or product edit was made.

The useful missing pieces are below. These are adaptations of architectural patterns; Codex Rust/Tokio or its protocol must not replace Muse's runtime. No measured performance regression or cause of the installed navigation expiry is claimed.

## 1. Give native navigation an explicit completion receipt and separate optional visual settling

**Priority:** first, because it makes the reported intermittent failure diagnosable and prevents unrelated animation from defining the entire command outcome.

**Codex evidence:** `codex-rs/app-server/src/outgoing_message.rs:64-73` retains request identity, cancellation, and a trace until its final response/error; `:294-301`, `:329-337`, and `:833-844` register, clean up on connection loss, and remove the context on final response. `:907-926` has a distinct write-completion acknowledgement rather than equating enqueue with delivery. These are lifecycle/observability patterns, not proof of an Electron animation fix. [Pinned request context](https://github.com/openai/codex/blob/a795f961be68383738e56ac396742b3e8451696a/codex-rs/app-server/src/outgoing_message.rs#L64-L73), [pinned delivery acknowledgement](https://github.com/openai/codex/blob/a795f961be68383738e56ac396742b3e8451696a/codex-rs/app-server/src/outgoing_message.rs#L907-L926).

**MuseBench now:** `electron/native-control-service.mjs:45-75` has trusted IPC, single pending request, claim identity, cancellation, and an 8-second timer. The reply handler checks the claim but does not independently reject `Date.now() > item.deadline`; a late reply can win if the event-loop timer is overdue. `electron/preload.cjs:12-14` compresses renderer failures to `error:true`. `src/ui/native-control-ui.ts:12-29` waits two animation frames and every pending/running finite animation in the app document, then repeats. A finite animation is not necessarily relevant to the destination, visible, or making progress. `:35-37` makes that visual wait part of successful `navigate`. `src/ui/App.tsx:434` owns the semantic navigation callback.

**Bounded implementation:** preserve request IDs and existing permissions. Add bounded safe phase/timing receipts (`sent`, `claimed`, `navigation-applied`, `destination-committed`, `visual-settle`, `replied`, `expired`), with no form values, transcript, paths, or provider-frame content. Check deadline again in the main-process reply handler, not only in the timer and claim path. Verify the requested destination after React commit using a target/revision predicate. Then wait only for relevant visible shell-transition work within a separate short visual budget. When the destination is verified but optional visual settling times out, return the verified UI plus an explicit visual-settle status; never report target success merely because time elapsed. An unverified destination remains unknown/failed, with no automatic replay. Keep screenshot capture's separate pixel-readiness contract.

**Tests:** deterministic claim/reply/deadline tests with an overdue timer and late reply; exactly one terminal receipt; cancellation before/after claim; detached renderer; paused finite/zero-rate and unrelated hidden animations; no animation-frame progress; target mismatch; reduced motion. Extend `test/native-control-service.test.mjs` and `scripts/native-control-smoke.mjs` with an isolated fixture profile. For real installed acceptance, collect a failing request's phase receipt before assigning a cause.

**Evidence limit:** `artifacts/native-control/diagnose-MIxc5A/report.json` recorded successful isolated navigation at approximately 1862 ms, 223 ms and 9 ms, despite many reported animation entries. `occlusion-j6nwam/report.json` recorded successful settings/code navigation at 241 ms and 1854 ms; its observed frame counters kept progressing. Those reports do not reproduce the installed 8-second failure. They do not establish animation suspension, occlusion, a renderer stall, IPC loss, or session load as the cause.

## 2. Bound controller-to-renderer delivery by consumption, not only producer cadence

**Priority:** second; this is a missing protection against a slow/hidden/reloading renderer, independent of whether it explains the native expiry.

**Codex evidence:** `codex-rs/app-server/src/transport.rs:141-178` uses a per-connection outbound writer. Disconnectable transports use `try_send`; a full queue disconnects that slow connection, while stdio deliberately awaits capacity. `transport_tests.rs:469-555` verifies one slow connection cannot block broadcast to a fast connection, and `:558` explicitly tests the different stdio rule. [Pinned transport](https://github.com/openai/codex/blob/a795f961be68383738e56ac396742b3e8451696a/codex-rs/app-server/src/transport.rs#L141-L178), [pinned slow-reader regression](https://github.com/openai/codex/blob/a795f961be68383738e56ac396742b3e8451696a/codex-rs/app-server/src/transport_tests.rs#L469-L555).

**MuseBench now:** `src/controller/index.mjs:305-313` already coalesces replaceable stream publications to 40 ms and immediately flushes control/terminal changes. However, `electron/main.mjs:166` sends each resulting complete state through `webContents.send` with no acknowledgement, in-flight limit, revision, or renderer consumption signal. `electron/preload.cjs:90-94` forwards each snapshot, and `src/ui/App.tsx:189-194` sets React state for each. Rate limiting the producer does not bound accumulated IPC work while a renderer cannot consume it. The controller also has multiple observers (notifications, Work, Sites), which must remain independent of renderer consumption.

**Bounded implementation:** introduce a shell-scoped state publisher with a monotonically increasing generation/revision, one in-flight snapshot, and one replaceable latest pending snapshot. Acknowledge consumption from the trusted preload/React boundary; send the newest pending snapshot on acknowledgement. Bound acknowledgement wait and detach/reinitialize the presentation subscription on renderer load/loss, without disconnecting active Muse work. Reattach with a fresh authoritative `controller.getState()` snapshot; ignore stale acknowledgements. Preserve durable controller processing and notification observers. Intermediate replaceable view snapshots may be superseded; approval, completion, and unknown-outcome facts remain in canonical controller state/receipts and must be present in the next delivery. Also guard `getState`/dispatch response application against an older revision overwriting a newer pushed state.

Do not copy Codex's disconnect-the-client action literally: an Electron renderer can detach its *view subscription* while the background engine continues owning work. Never replay a send/approval/navigation action on reattach.

**Tests:** a fake renderer holds acknowledgements while 10,000 snapshots arrive; assert at most one in-flight plus one latest pending snapshot and eventual newest-state delivery. Verify a second observer remains responsive; stale acknowledgements cannot release a replacement renderer; a terminal or approval state survives coalescing; dispatch/initial read races cannot roll back state; background-engine hide/reopen preserves active work. Add one isolated real Electron burst/reattach check with input-latency and pending-depth measurements, using fixture events only.

## Deferred candidate: full transcript materialization before display publication

**Decision:** defer implementation until a reproducible burst measurement demonstrates material cost. The two recommendations above address concrete request/delivery boundaries first. This is not a selected deliverable.

**Codex evidence:** `codex-rs/tui/src/tui/frame_requester.rs:92-125` records a next draw deadline and coalesces requests before producing one draw notification. `codex-rs/app-server/src/thread_state.rs:216-230` provides active-turn ID and metadata reads specifically without cloning the full item history. `codex-rs/tui/src/app/thread_event_buffer.rs:8-34` additionally shows identity-bound adjacent text-delta merging with a finite byte ceiling; its replay eviction is not suitable for MuseBench's canonical event fold. [Pinned draw scheduling](https://github.com/openai/codex/blob/a795f961be68383738e56ac396742b3e8451696a/codex-rs/tui/src/tui/frame_requester.rs#L92-L125), [pinned metadata reads](https://github.com/openai/codex/blob/a795f961be68383738e56ac396742b3e8451696a/codex-rs/app-server/src/thread_state.rs#L216-L230).

**MuseBench now:** C08's metadata-only status reader is already used by inventory/activity (`src/runtime/status.mjs`, `src/controller/index.mjs:287-295`) and its downstream 40 ms stream publication is already implemented. The remaining earlier work is concrete: `reference/patchlight/adapter/session-adapter.mjs:44-46` clones its entire message map for each observer; `:185-203` emits after a text delta. `src/runtime/index.mjs:172-174` clones a full runtime snapshot for each observer. `src/runtime/exec.mjs:88-89` does the same on each update. `src/runtime/selector.mjs:8-9` ignores its subscription's supplied snapshot and calls `runtime.snapshot()` again. All this occurs before `publishRuntime` can coalesce, and `src/controller/index.mjs:825` processes message history before that display timer.

**Bounded implementation:** first remove the selector's redundant snapshot call where a current supplied snapshot can be forwarded safely, and share one detached snapshot per emission when observers cannot mutate each other's view. Then consider an additive lightweight change subscription with owner/connection epoch, revision, and change kind. Fold and validate every native event immediately. For *pure content changes only*, schedule one display materialization at the existing cadence and read the latest authoritative snapshot once. Flush immediately before any approval/input, ownership/session change, terminal/unknown result, explicit navigation, save/close, or queue transition. Do not debounce permission verification, native sequence checks, durable completion accounting, or command admission. Retain legacy snapshot subscriptions until Work/Sites/controller consumers are migrated deliberately. Preserve immutable-observer behavior rather than sharing mutable protocol state.

**Tests:** extend `test/runtime-selector.test.mjs`, `test/runtime.test.mjs`, `test/exec-runtime.test.mjs`, and `test/controller-drafts.test.mjs`. Count full snapshot materializations during an injected 10,000-delta burst; assert exact final text, fewer copies proportional to display flushes, correct owner, immediate pending input/terminal settlement, and flush on close. Measure controller work/input latency for a long transcript and multiple active fixture chats before and after. This is an extension below C08's current batching boundary, not a claim that batching is missing entirely.

## Ideas rejected or already covered

- Generic “coalesce streaming at 40 ms,” metadata-only sidebar reads, single-flight search/context reads, and sidebar memoization are duplicates of C08. They should not be counted as new deliveries.
- Generic reconnect/retry is unsafe. `src/runtime/index.mjs:185,208-218,344-378` already uses epochs, explicit teardown and owner guards; `reference/patchlight/adapter/session-adapter.mjs:59-99` restores a snapshot with identity/cursor checks. The roadmap already requires no replay of unknown outcomes. Retain those properties; renderer *view* reattachment is narrower than reconnecting a native session.
- Codex resume-response/snapshot/request replay ordering (`app-server/src/request_processors/thread_lifecycle.rs:1231-1264`) is a useful review reference but not a missing Muse feature proven by this pass. Muse already buffers opening events and restores pending requests. No native schema or capability should be invented to imitate Codex.
- Do not copy notification opt-out fields into the Muse initialize handshake; the pinned Muse SDK/protocol must demonstrate support first. Filtering raw approval, permission, or completion events is unacceptable. Local presentation subscriptions can use bounded projections without changing that handshake.
- Increasing 8 seconds, adding retries after unknown navigation, disabling all animations, enabling `backgroundThrottling:false`, or blaming occlusion are not evidence-backed fixes. The supplied isolated reproductions passed.
- The optional background engine, work activity, durable history, child control, context continuity, and linked chat work are already roadmap items/deliveries; they are not new runtime recommendations.

## Review boundary

This report validates source paths and contrasts observed implementations. It does not execute upstream, benchmark MuseBench, prove installed acceptance, or attribute the intermittent expiry. Suggested tests are implementation gates, not checks already passed. Only this report was written.

## Planning interfaces for the two selected deliverables

- Native completion: keep `createNativeRenderer({window,ipcMain,trusted}).call(operation,args,signal)` and the existing MCP tool names. Internally extend the request with a bounded phase receipt keyed by existing `id`; use `finishOnce(...)` for success, rejection, cancellation, loss and deadline. Add a UI helper shaped like `waitForNativeDestination({target,revision,deadline,signal})` before optional `settleNativeTransition({scope,maxMs,signal})`. The destination helper must observe a committed render for the requested target; do not substitute a fixed sleep. If returning extra metadata would change the established MCP result shape, preserve top-level inspection fields and add an optional `navigation` object with verified target/commit and `visualSettled` status. Never expose full internal exceptions.
- Renderer flow control: extract a presentation publisher shaped like `createRendererStatePublisher({send,readState,now,setTimer}).publish(state)`, `.ack({generation,revision})`, `.attach()`, `.detach()`, `.close()`. Main and preload validate generation/revision and trusted sender. Keep one in-flight and one pending latest state; acks refer only to state consumption, never request execution. Use an optional envelope `{generation,revision,state}` for shell IPC and unwrap it at the bridge so existing UI consumers can migrate in one bounded change. A common revision gate must cover pushed state, initial `getState`, and dispatch-returned state; attaching a generation requires a fresh full snapshot. Do not feed renderer acks into notification, Work, Sites, native-owner or persistence logic.
