# T3 Code workflow comparison: keep Muse, improve the daily interface

Read-only source review, 30 October 2026. MuseBench baseline: `0f83414eb387e1a9120c38aeb435d5bba2fb102f`. T3 Code snapshot: `e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa` from `pingdotgg/t3code`. Upstream links below are pinned to that commit. No upstream code was executed or installed, no model calls were made, and no product or roadmap files were changed. This is static implementation evidence, not a runtime acceptance claim.

The best additions are small improvements to composing, revisiting and organizing work. MuseBench already has most of the substantial underlying workflows. Adapting T3's provider stack or UI framework would add cost without delivering the user's requested benefit.

## Ranked recommendations

### 1. Save several unsent prompts in a recoverable prompt shelf

**Benefit:** Park an unfinished request, write a quick follow-up, then restore the original text and screenshots without creating another chat or placing something in an executable queue.

**T3 evidence:** [Composer guide, lines 166–175](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/docs/user/composer.md#L166-L175) describes saving and restoring prompts. This is implemented: [`promptStashStore.ts:15,93–108,145–168`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/web/src/promptStashStore.ts#L93-L168) bounds entries, persists before publishing changes and exposes durability outcomes. [`useComposerStash.ts:157–194`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/web/src/components/chat/useComposerStash.ts#L157-L194) verifies file/environment identity before taking an entry and aborts on a changed destination. [`useComposerStash.ts:446–567`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/web/src/components/chat/useComposerStash.ts#L446-L567) blocks unfinished attachment intake and writes before clearing the composer.

**Actual MuseBench gap:** Durable drafts already exist. `src/controller/code-drafts.mjs:3–42` stores them transactionally, while `src/ui/useCodeDraft.ts:5–7` and `src/controller/index.mjs:479–488` key one current draft to each project/chat. `src/shared/types.ts:160` exposes saveCodeDraft for that one draft. There is no second parked draft list or restore UI. Do not describe this recommendation as “add persistent drafts.”

**Minimum integration:** Keep SQLite as the authority. Add a bounded local prompt-shelf table/store with project/chat provenance, saved time, text, file hashes, existing image references and chat/plan mode. Expose save/list/restore/remove through the same controller and bridge boundaries. Saving must atomically persist the shelf item before replacing the current draft. Restoring should append or explicitly replace an occupied draft, retain the saved item until the replacement is durable, and revalidate project/file/image ownership. Present “Save for later” in Add to chat and a small shelf count/menu; defer the Ctrl+S shortcut if it conflicts with existing desktop/browser behavior. Queuing and saving remain different actions.

**Tests:** Extend `test/code-drafts.test.mjs` and `test/controller-drafts.test.mjs` with failed writes, restart, chat switch during restore, occupied drafts and attachment ownership. Shared preview and isolated Electron: text+image save, write failure leaves original intact, restore after reload, remove, keyboard operation, zero runtime.send calls. Use the existing `scripts/chat-navigation-smoke.mjs` and `scripts/code-chat-relations-smoke.mjs` pattern for preview/desktop parity.

**Risks/prerequisites:** Image retention must account for shelf references before images can be garbage-collected. Choose and disclose a storage bound; do not silently discard the oldest entry. Recent-context capsules cannot be copied as fresh authority: either retain their exact binding and revalidate or restore them as readable text requiring inclusion review. No native Muse API change is needed.

### 2. Move between workspace areas with F6 and browse the sidebar with arrow keys

**Benefit:** Reach the conversation, composer, sidebar and visible changes panel without tabbing through every chat and button. This is especially useful when many chats are open and for keyboard/screen-reader users.

**T3 evidence:** [Keyboard focus guide:15–35](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/docs/user/keyboard-focus.md#L15-L35). Actual [`workspaceFocus.ts:12–21,100–179`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/web/src/lib/workspaceFocus.ts#L100-L179) declares ordered areas and restores a visible control; [`workspaceFocus.ts:223–278`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/web/src/lib/workspaceFocus.ts#L223-L278) respects popup/modal boundaries and cycles visible areas. The file also cancels delayed focus requests on user input instead of stealing focus after an async mount. `apps/web/src/components/sidebar/SidebarThreadRow.tsx:835–855` implements F2 rename, and the row roots use `tabIndex={-1}` at 1210/1398 as part of its sidebar navigation system.

**Actual MuseBench gap:** Global shortcuts in `src/ui/App.tsx:290–299` cover search/settings/sidebar/new chat, not workspace-area navigation. `src/ui/ChatSidebar.tsx:49–55` implements Alt+Shift+arrow reordering, and `60` handles Context Menu/Shift+F10; plain arrows do not browse rows independently of activation. `src/ui/WorkspacePanels.tsx:13–36` already traps modal focus and restores its opener. Preserve that behavior rather than claiming accessibility is absent.

**Minimum integration:** Add a small shared UI focus controller, named area attributes on existing sidebar/conversation/composer/details containers, last-focused control tracking, and F6/Shift+F6 in Electron with Ctrl+F6 browser fallback. Use a flattened list of currently visible project/chat rows for one roving tabindex; plain Up/Down move focus, Enter activates, Left/Right collapse/expand, F2 calls the existing rename flow. Preserve Alt+Shift reordering and context menu controls. Avoid new controller/native APIs.

**Tests:** Shared preview: forward/backward wrap, hidden and collapsed regions skipped, modal/menu/slash-palette boundaries, sidebar expansion, F2 and existing reorder keys. Isolated Electron verifies actual Windows F6 handling and visible focus. Regression: an incoming state update or async panel mount must not steal focus; transcript navigation must not jump scroll or stop following an active turn merely because focus moved.

**Risks/prerequisites:** Scope to Muse Code first; embedded Personal pages and preview webContents have different focus ownership. The native semantic-navigation receipts in `src/ui/SemanticNavigation.tsx` already exist and are a separate automation contract; this feature should not alter their meaning.

### 3. Quote selected assistant text into an unsent draft, with a return-to-source action

**Benefit:** Ask “change this part” about an exact passage in a long response without manually copying a whole message or opening another chat.

**T3 evidence:** [Composer guide:117–134](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/docs/user/composer.md#L117-L134). Actual [`AssistantSelectionToolbar.tsx:122–130,177–205`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/web/src/components/chat/AssistantSelectionToolbar.tsx#L177-L205) creates a versioned citation containing thread/message identity and captured selection, enforces a text bound and offers a keyboard-accessible Cite action. [`citationProcedure.ts:37–89`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/web/src/components/chat/citationProcedure.ts#L37-L89) bounds history paging and keeps saved text when its source is missing. [`AssistantCitationSource.tsx:205–214`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/web/src/components/chat/AssistantCitationSource.tsx#L205-L214) explicitly distinguishes changed source text from the immutable quote.

**Actual MuseBench gap:** Existing `src/ui/ChatLibrary.tsx:19–31` and `src/ui/HistoryMessages.tsx:14` can already add a saved message excerpt to a draft, and `src/ui/useCodeDraft.ts:19–23` guards the destination and 16k bound. Existing `src/ui/ResponseActions.tsx:33–40` offers copy/read/feedback/fork/reply changes, but no direct quote action on a selected live reply. Library excerpts become plain text; there is no structured quote record or source-return control. This is an incremental usability improvement to existing excerpt functionality.

**Minimum integration:** Add a modest “Quote selection” action to the rendered assistant message, with an accessible whole-response fallback. Capture only selections wholly inside one committed assistant message; reject active/changing text. Retain immutable `{taskId,messageId,text,sourceDigest}` metadata in the draft, display a small quote card with remove/open-source, and flatten it into explicitly attributed quoted text only at the existing context boundary. Reuse readChatHistory for source inspection; retain the saved quote if the message was removed or changed. Keep editable prose in the existing textarea; a rich editor/chip framework is not needed for a first slice.

**Tests:** Selection inside code/lists/links, cross-message selection rejection, active-stream rejection, existing draft preservation and exact owner on chat switch; restart/queue snapshots retain the selected text; stale/deleted source preserves quote and shows an honest message; large/Unicode quote enforces the combined context limit without slicing a character. Preview + Electron verify source inspection, keyboard fallback and zero sends until explicit submit. Reuse `scripts/chat-read-smoke.mjs` and run-change draft tests.

**Risks/prerequisites:** DOM rendered offsets are not guaranteed to match raw Markdown; store exact selected text and a digest, not an invented raw-source line range. Quoted content stays untrusted source content. Extend CodeDraft/Message serialization and queue capsule validation together, or limit the first release to a plain attributed quote with an explicit source button while drafting.

### 4. Snooze an idle chat until later, without running anything when it returns

**Benefit:** Put work aside until tomorrow while keeping it visibly distinct from archived work. MuseBench archive currently enters a 30-day deletion policy, so it is a poor substitute for a personal follow-up reminder.

**T3 evidence:** [Thread guide:285–300](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/docs/user/thread-sidebar.md#L285-L300) distinguishes snooze from auto-resume. Actual [`Orchestrator.ts:3306–3350`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/server/src/orchestration-v2/Orchestrator.ts#L3306-L3350) validates future wake times and rejects pending requests or ordinary queued runs. [`Orchestrator.ts:3415–3433`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/server/src/orchestration-v2/Orchestrator.ts#L3415-L3433) updates snooze metadata idempotently. [`Sidebar.logic.ts:121–147`](https://github.com/pingdotgg/t3code/blob/e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa/apps/web/src/components/Sidebar.logic.ts#L121-L147) handles clock advance across laptop sleep without repeated re-renders. `Orchestrator.ts:5342–5362` wakes on an explicitly sent message while keeping automatic background notifications from overriding snooze.

**Actual MuseBench gap:** `src/shared/types.ts:19,61` has pinned/archive metadata and actions but no deferred return time. `src/shared/sidebar-model.mjs:13–23` only removes archived items from normal collections. `src/controller/index.mjs:410` deletes archives after 30 days; `1005–1008` archives/pauses queues. `src/ui/ProjectOverview.tsx:37` discloses the retention policy. Existing local Code schedules start bounded prompts; a snooze must not be built as a schedule that calls Muse.

**Minimum integration:** Add `snoozedUntil` and explicit snooze/wake actions, a collapsed Snoozed shelf with time labels, and tomorrow/custom-time choices in the current chat menu. First slice only allows idle chats without pending input, armed goals or runnable queues. On due time/restart, return it to active visibility and optionally add one idempotent metadata-only activity-inbox event. Never call send/resume/queue or change native session authority. Display “returns when MuseBench is open” rather than promising OS wakeup while the app is closed.

**Tests:** Inject clock in unit/controller tests: expiry, app restart after expiry, resnooze, archive/delete, timezone/DST display, laptop sleep, duplicates, manual wake and pending-work rejection. Preview/Electron: time label, collapsed shelf, keyboard action, restart persistence, exactly one inbox return and zero model/native send calls.

**Risks/prerequisites:** This adds another sidebar state; use one shelf and two initial presets rather than copying T3's full settle/working/active taxonomy. Preserve side-chat grouping and pin order explicitly. Avoid automatic settlement/cleanup and usage-reset auto-resume in this scope.

## Reviewed but deferred or excluded

- **Question attachments:** The T3 guide is backed by actual per-question composer targets (`apps/web/src/components/chat/ChatComposer.tsx:633–665`) and question-keyed attachment helpers (`questionAttachments.ts:11–25`). MuseBench's accepted answer contract rejects fields beyond questionId/selectedLabel/selectedLabels/freeText (`src/shared/user-input.mjs:14–17`). A visible file button would require new native contract proof and safe receipt handling; do not emulate file delivery by hiding paths inside answer text.
- **Generic files, big-paste attachments, rich Markdown editor:** T3 docs promise 120k text and automatic files for a 32 KiB paste; MuseBench bounds drafts at 16k, file context to 8 reviewed source files/24k chars (`CodeContext.tsx:22`) and screenshot intake separately (`ChatComposer.tsx:52`). These are native/context/retention changes, not a small editor port. A rich editor also risks Markdown fidelity, IME and keyboard regressions. Safe overflow feedback could be investigated separately without increasing budgets or silently truncating input.
- **Prompt history recall:** T3 implements text-only recall in `components/chat/composerPromptHistory.ts:141–188`, filtering attributed automatic messages and not reconstructing missing attachment records. Useful lower-cost polish after the four above; MuseBench user messages do not yet uniformly expose authored-vs-automation provenance, so do not recall scheduled/goal/workflow prompts as if manually typed. No rewind behavior is implied.
- **Prompt links:** T3 `components/promptLinks/linkedPrompt.ts:8–53` strips/warns about hidden characters and stages drafts, asking before overwriting. Sharing links would need a MuseBench URL/protocol and destination-resolution contract; no current requirement justifies importing a hosted landing page or adding provider parameters.
- **Triage:** Actual `hooks/useStartTriage.ts:29–85` opens a projectless draft and `apps/server/src/triage/TriageService.ts:50–59,127–169` resolves/clones versioned source. MuseBench already has connection diagnostics and a local copyable issue report (`src/ui/CommandDialog.tsx:32`). Model-assisted triage, network cloning and new logging/privacy policy are unnecessary for this interface pass. A separately reviewed redacted diagnostics bundle may be useful later.
- **Integrated commits/push/PR/watch:** Actual T3 `components/GitActionsControl.logic.ts:21–36` offers commit/push/PR actions and source-control docs cover host/account/auto-merge behavior. MuseBench currently reads sanitized repo URL/branch (`src/shared/project-git.mjs:16–20`) and already reviews run changes. A full VCS-host client adds authentication, irreversible actions and background inference. It is a future product decision, not an immediate Muse UI adaptation.
- **Automatic worktree cleanup, auto-pull, auto-resume at reset, webhook runs and multi-model fan-out:** Excluded. They change execution, retention, permission or provider contracts and are not prerequisites for the four recommendations.

## Verification boundary

All findings above were checked against source, including both T3 web components and server orchestration. Existing test files were inspected as integration targets, not executed. No provider interoperability, desktop appearance, accessibility tree, keyboard behavior or application acceptance was tested during this read-only research. Implementation should use MuseBench's shared preview plus disposable Electron fixtures and assert zero model calls. Keep native Muse and all existing permission/data identities unchanged.
