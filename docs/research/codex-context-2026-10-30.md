## Two selected gaps

### 1. P1 — Explicitly replace or retire app-authored instructions in continued sessions

**Problem:** Changing/clearing Personal instructions or Project instructions affects the next composed prompt, but does not explicitly retire the old instruction text already submitted to a durable native session. `src/shared/chat-context.mjs:10-22` always includes nonempty current sections and omits empty ones; the native continuation preamble explicitly retains previous state. `src/controller/index.mjs:718-741` sends that prompt; settings mutations at `:968` and `:1105` only update the saved value. `src/ui/Preferences.tsx:115` and `src/ui/CommandDialog.tsx:25` describe clearing as stopping inclusion, which is accurate for new app text but says nothing about older native history. Current receipts hash current instruction text (`src/controller/context-receipts.mjs:3-4`) without a transition record.

**Codex evidence:** `codex-rs/core/src/context/world_state/agents_md.rs:11-13,48-87` distinguishes known/unknown/absent prior state, emits replacement/removal notices and skips unchanged known snapshots. `codex-rs/core/src/context/world_state/managed_developer_instructions.rs:18-21,124-157` applies the same rule using content hashes. Its `managed_developer_instructions_tests.rs:9-80` checks update, removal, repeated unchanged state and legacy/unknown history. The transferable element is explicit instruction transitions; MuseBench must not copy Codex's native AGENTS loading policy or developer-message authority.

**Bounded design:** Give only the two *app-owned* sections stable identities and revision/digest metadata, scoped to exact project/task/native-session ownership. On ordinary sends, state that the supplied current section replaces earlier app-supplied instances; emit an explicit scoped removal notice after clearing a previously sent section (or when earlier state is unknown). Full current text should continue accompanying requests initially. Do **not** omit unchanged instructions merely because an app receipt says they were sent: Muse retained-context membership after compaction is not proved. These notices convey current intent; they cannot erase prior provider history or guarantee model compliance. Do not relabel repository AGENTS/CLAUDE files, skill bodies or direct user requests as replaced by the app.

Update transition state only from the existing accepted-input ownership path (`src/controller/index.mjs:818-834`), never from preview/composition, setting save, rejected send or unknown request outcome. Preserve existing no-replay guards. Old records without state require conservative unknown handling. A native fork inherits older history, so initialize its app-section state from verified fork provenance or unknown; a fresh linked side chat starts independently. Attach bounded transition metadata to the existing context receipt. Queued delivery uses the exact text composed at its existing admission boundary and records its actual instruction revision; it must not advance state on queue edit/preview.

**Tests:** composer/controller fixtures for A→B→empty, empty first request, unchanged current text, settings changed in another chat, independent projects, accepted/rejected/unknown sends, restart with old schema, fork versus fresh side chat, compaction and queue delivery. Assert exact outgoing notices and receipts, not model obedience. Shared UI checks should explain that clearing stops future inclusion and sends a retirement notice on the next request; historical content is retained. Works through existing `runtime.send` for supported exec/MSP sessions, requiring no new native API or inference. Native retention/deduplication remains out of scope.

### 2. P2 — Preserve a useful bounded preview of oversized discovered-tool results

**Problem:** `src/runtime/discovery-gateway.mjs:55-65` validates the final result, then replaces every result above the fully encoded 128 KiB response limit with an outcome/truncation/error receipt containing **none** of its content. Completed/failed outcome is correctly retained and uncertain calls are correctly not retried. This leaves a successful large result unusable even if its beginning/end contains the answer. `test/discovery-mcp-gateway.test.mjs:20` currently enshrines only truncation/outcome behavior. This affects reviewed third-party discovery sources, not arbitrary native tools.

**Codex evidence:** `codex-rs/utils/output-truncation/src/lib.rs:24-68` formats bounded text truncation with omission information; `:71-113` replaces oversized MCP results with a bounded textual preview, drops structured-content authority, preserves `is_error`, and repeatedly checks the complete serialized replacement to account for JSON escaping. `codex-rs/utils/string/src/truncate.rs:26-73` provides Unicode-safe prefix/suffix truncation and a hard-bound marker-aware alternative. `codex-rs/core/src/context_manager/history.rs:600` applies truncation when admitting output into history.

**Bounded design:** After the existing original schema validation and outcome determination, produce an explicitly labeled **preview**, preserving source/catalog/tool identity, exact failed/completed outcome, original encoded byte count and omission count. Include bounded UTF-8-safe text head/tail plus marker; check `wireBytes` on the complete final response and shrink as needed. Never return a shortened object as if it still satisfies the tool's structured output schema. Never inline partial image/audio base64, arbitrary metadata or executable content; media-only results retain a receipt explaining omission. Keep transport receive limits, source verification, permissions, no-retry and cancellation semantics unchanged. Initial implementation should not add persistent output storage or new arbitrary file read tools.

**Tests:** success and `isError` large results, schema-valid structured output converted to explicitly non-authoritative preview, Unicode/combining characters, many quotes/backslashes, exact boundary values, media-only output, multiple content blocks, original source receipt and call count unchanged. Assert complete encoded JSON-RPC frame <=128 KiB, omission marker and text endpoints, unknown outcomes never retried. Add isolated stdio/remote fixture parity and scripted native gateway acceptance only if parent authorizes that gate; no live model inference needed for source checks. A useful preview is measurable; lower token use or better model outcomes are not established.

## Rejected/deferred ideas

- **Copy Codex AGENTS.override.md/filename fallbacks or its limits into Muse selection:** upstream `codex-rs/core/src/agents_md.rs:42-45,68,272-295` implements a different native contract. Changing MuseBench's inspector would misrepresent Muse; additional filenames must first be qualified against pinned Muse. No instruction-file/profile edits are proposed.
- **Copy Codex's skill catalog compression/aliasing/delta injection:** `codex-rs/ext/skills/src/render_dedup.rs:40-56,86-143,146-200` operates on native model-visible inventory, fingerprints and alias plans. Muse already supplies its own catalog cost/lazy-loading semantics. App UI filtering/compression does not prove smaller provider context; replacing the native loader could duplicate or suppress instructions.
- **Provider prompt cache keys, Responses WebSockets, prewarming or client-side guessed cache hits:** `codex-rs/core/src/client.rs:707-738` derives affinity from Codex's native session/provider metadata. MuseBench uses native Muse transports and has no validated equivalent request API. Keep actual reported cached tokens; do not add OpenAI-specific keys or hidden requests. No cache or latency gains claimed.
- **Suppress repeated current instructions solely from an app digest:** Codex owns retained model history; MuseBench does not. Compaction/restore can invalidate this inference. Proposal 1 transfers explicit replacement/removal semantics while retaining the full current section.
- **Automatic cross-project memory mining, summary generation or background consolidation:** current MuseBench memory is deliberately an explicit 1,500-character local preference field (`src/controller/index.mjs:205,1105`, `src/ui/Preferences.tsx:115`), plus 4,000-character project instructions. Codex has distinct scoped search/read tools (`codex-rs/ext/memories/src/local/search.rs:18-97`, `local/read.rs:12-50`) and an independent write/consolidation system. A user-reviewed project notebook with bounded search could be a future standalone design, but is not selected here: it needs new storage, retention, deletion, provenance and UI contracts and is less immediate than the two proven gaps. Do not read/write Codex personal memory or reuse hidden native memory stores.
- **Auto-compaction tuning, precomputed summaries, tool-output replacement inside native history:** OC06 already records those as unsupported pending a pinned contract and separately authorized acceptance. Upstream internals cannot establish Muse support.
