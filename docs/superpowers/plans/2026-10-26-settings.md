# Native settings implementation plan

> Execute inline with superpowers:executing-plans; review the complete change after validation.

**Goal:** Expand the existing profile-accessible settings into a searchable Claude-style dialog with real MuseBench controls.

**Architecture:** Preserve the v1 preference key and default behavior. Keep appearance and new-chat defaults in validated renderer preferences, global instructions in the existing controller, and notification delivery behind a narrow trusted IPC method. Reuse existing account, skills, usage, export and dictation capabilities. No authentication partition or sandbox changes.

**Tech stack:** Electron, React, TypeScript, Node tests and Playwright Electron.

- [x] Test preference migration, malformed values, search matching, native notification transitions and no replay on restore.
- [x] Implement preference extensions, new-chat defaults, bounded notifications and grouped searchable settings. General, Notifications, Voice, Shortcuts; Muse Code, Memory, Skills, Muse connection; Account, Usage & billing, Data & privacy, About.
- [x] Test the real Electron UI: search and keyboard navigation, tabs, persistence, new-chat defaults vs existing chats, memory save, honest unavailable states, export cancellation and responsive light/dark presentation.
- [x] Build and run regression checks, compare sandbox/login boundaries, package exact validated sources and reopen the normal app.

## Evidence and decisions

Observed the installed Claude application's General and Claude Code panels, without changing preferences. General matches the supplied screenshot; Code shows subscription information, session state classification and code appearance. Codex/ChatGPT reference used supplied screenshots and official documentation because Windows computer-use guidance excludes the ChatGPT desktop UI.

References checked 2026-10-26:
- https://learn.chatgpt.com/docs/reference/settings (official former Codex app settings route)
- https://code.claude.com/docs/en/desktop
- https://support.claude.com/en/articles/8887527-customizing-your-appearance-settings

Selection: theme, fonts, text size, transcript width, composer keys, notifications, reasoning/approval defaults, explicit instructions, skills, account and data access suit the existing app. Cloud worktrees, parental controls, password management, provider memory and unrelated integrations need independent backends and are not represented by inert switches. Transcript width applies to Muse Code. Appearance changes already supported by the personal service remain synchronized through its existing bridge. Notifications contain generic task status, not prompts or project paths; default off and delivered only while the window is unfocused. Existing chats retain their own run options. No model request is made by changing a setting.

Validation: 361 unit tests, 80 packaged UI checks, native Windows notification show event. Source and packaged files match. Review findings fixed, including exact-label search, normalized memory saves, responsive category groups, speech availability refresh, and active/pending run guards. See docs/VALIDATION.md.
