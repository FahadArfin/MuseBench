# Native-feeling Muse conversation

The user wants the actual Muse conversation and composer to match the existing Codex-like MuseBench shell, retaining login and sandbox. Keep the official controls and document alive: CSS presentation is the chosen implementation because it preserves attachments, streaming, approvals, editing, selection and sending. A duplicated React transcript/composer would require message extraction and fragile behavioral synchronization; a consumer API replacing the hosted client is not documented in the already researched official sources. This is a visual integration, not a replacement service client.

Use observed Muse DOM hooks for the chat column, message roles, assistant bodies, bubbles, prose and composer chrome. Match the local 800px column, 13/14/16px transcript sizes, 1.7 line height, plain assistant replies, 18px user bubbles and 16px two-row composer. Keep the actual textarea, attachment/send/stop controls, keyboard handling, disabled and streaming states. Style rich text within its message container, constrain code/table overflow, and retain approval/status controls. Do not hide consent, approval, login, errors, or locked-composer notices. No automatic sends or attachments.

Appearance is a finite local-to-main command: theme dark/light, textSize small/medium/large, font system/mono, reducedMotion boolean. Main passes it to the presentation adapter for retained and new views. System theme resolves in the trusted local renderer. Original-layout mode removes all presentation changes without reloading or changing drafts. Theme changes must not reset that choice.

New CSS belongs in electron/personal-chat-style.mjs and is applied only to recognizable Muse application chat surfaces on the exact Muse origin. No remote preload, Node/workspace bridge, token/cookie reads, account mutation, API replacement, or sandbox changes. Preserve the separate Meta AI Chat session. Keep production user content out of saved screenshots/reports; use fictional fixtures for visual artifacts, numeric/boolean checks for the live account.

Verify dark/light/mono/size/reduced-motion, narrow layouts, long code and tables, streaming/disabled controls, text selection, draft identity across preference/layout changes, late hydration, and auth/unrecognized-page guards. Exercise an unsent live draft and then clear only that test draft. Package the exact validated source, retain a recovery archive, and reopen the app.
