# T3-inspired Muse workflows

User direction: keep Muse as the backend; research T3 Code, select worthwhile workflow/interface additions and implement them. This design makes the delegated selection explicit. Baseline: `0f83414eb387e1a9120c38aeb435d5bba2fb102f`. Research snapshot: `pingdotgg/t3code@e9a11d4a8261f4c65e385a2b6d2ec3bd6de48caa`.

## Approach

Adapt small app-owned mechanisms to the existing React/Electron/SQLite architecture. Do not transplant T3's provider stack, editor, state library or server. Shared UI and bridge contracts keep browser preview and desktop aligned. Existing session, permission, context and release identities remain authoritative.

## Selected additions

1. **Reading continuity (T301).** Remember a bounded 100 chat/project reading positions in memory: stable message anchor, relative offset, fallback scroll offset and follow intent. Restore on returning to a chat; never display the previous chat as a placeholder. Upward user input releases following immediately, even within the current 100px end band. Jump to latest re-arms following. A bounded layout correction cancels on new input/navigation, respects reduced motion and coexists with find/minimap jumps. A missing retained anchor falls back safely. Stabilized restoration tolerance is 4px.
2. **Search all captured chat history (T302).** Extend the existing Ctrl+F ChatFind rather than introducing another competing search toolbar. Preserve visible formatted-text search; offer a clearly labeled saved-history scope that reads bounded occurrence results using project/task/query/cursor identity. Next/previous includes repeated occurrences, older-than-window messages and matches beyond the first excerpt. Reveal out-of-window results in a compact saved-text reader with one active literal highlight and honest capture coverage. No full-history renderer load; stale responses cannot replace a newer query/chat. Navigation wraps with an explicit indication; unavailable totals are not invented.
3. **Saved prompts (T303).** Add Save for later and a compact saved-prompts entry in the composer Add menu. Store up to 20 full current drafts per project/chat in a separate SQLite table: text, existing file/image references and mode. Save succeeds durably before clearing. Restore swaps an occupied current draft into the vacated shelf slot atomically, so no destructive overwrite prompt is needed and no text disappears. Validate owner, files/images and limits with existing intake rules. Full shelf rejects new saves without eviction. Unfinished uploads and bound recent-context capsules cannot be parked without first resolving/removing that capsule. Entries survive restart; delete is explicit; no enqueue/send/run is implied. Attachment retention includes shelf references.
4. **Quote a response (T304).** A small Quote action captures a selection wholly within one settled assistant reply, or the full reply when no selection exists. Append readable attributed blockquoted text to the existing unsent draft using its 16,000-character limit; reject oversize without truncation and preserve prior text. Capture displayed selection verbatim without claiming Markdown line offsets. Include stable source chat/message IDs in attribution and provide a source reader while staging. This first slice deliberately uses durable ordinary draft text, so existing saves/queues/restart work without a new rich context codec. Source changes/deletion never rewrite saved quote text. Active replies, cross-message selections and destination changes reject safely.
5. **Keyboard workspace navigation (T305).** F6/Shift+F6 cycle visible Code sidebar, conversation, composer and details areas, retaining last valid focus per area. Ctrl+F6 is a browser fallback. Skip hidden/inert regions and do nothing inside dialogs, menus, slash palettes or Personal webviews. Sidebar plain Up/Down/Home/End move focus among visible chat rows without opening them; Enter opens, F2 uses existing rename. Preserve existing reorder/context-menu shortcuts. Focus changes must not change reading position or dispatch provider work. Keep existing project disclosure buttons rather than inventing tree roles.
6. **Native retry visibility (T306).** Observe supported SDK 1.4.14 retry notifications through existing native identity/cursor gates. Project bounded attempt/count/delay data as a nonterminal status, with no raw provider error strings. Show that Muse scheduled a retry, not that MuseBench has retried. Clear on native progress, terminal, disconnect or session replacement. Malformed/foreign/stale/conflicting events follow existing validation semantics. No app timer resubmits, no queued work admission, no new command IDs, no authentication/permissions change. Fixtures prove projection only; actual host delivery stays unverified without a compatible runtime and authorized observation.
7. **Typing responsiveness (T307).** Measure the existing outer transcript render path on a fixed 150-message fixture, then introduce the narrowest stable transcript/row memo boundary that demonstrably avoids unchanged message work during composer typing. Preserve content and handler freshness, images, run activity, selection, quoting, search and scroll. Do not replace transport or add virtualization/dependencies. Report work counts and latency honestly; do not promise model-speed improvements. If measurement shows no reducible work, record the result and retain current architecture rather than shipping speculative complexity.

## Constraints

Saved-prompt transactions also fence every mutation of the affected draft owner from pending-save drain through acknowledgement. Temporarily block input, programmatic appends, file/image completion, send/queue and another shelf operation; reconcile the returned durable draft without a blind resave. Maintain a per-owner generation to reject stale acknowledgements after navigation. Roll back both the SQLite draft and controller mirror consistently. On chat moves, migrate text-only shelf entries transactionally and reject moves with file/image-bearing entries until those entries are removed or restored and resolved. Archive/restore retains entries; permanent deletion and archive expiry remove owned shelf rows and release attachment references. Deleted owners must not retain orphan shelf data.

Visible find retains stable message/occurrence identity during streaming and rehighlights without recentering. Only explicit query/result navigation reveals a match and releases following. If a selected occurrence disappears, choose the nearest remaining ordinal without scrolling until an explicit navigation request.

- Muse remains the only coding backend; no new providers or subscription aggregation.
- No paid model requests, upstream executable runs, account/billing/security permission changes or personal-session test mutation.
- Shared preview and Electron behavior, accessible names/focus, narrow layouts and reduced motion are required.
- Preserve existing draft/context limits, session identities, permission/admission gates and stored data.
- Tests use disposable profiles and counted fake runtime boundaries when asserting zero sends; no constant zero-call report fields.
- Native fixtures, source tests, CI, published artifacts and installed UI are separate evidence classes.
- Review and push each completed feature; final Windows x64 install only after exact-head required CI/release/hash checks and fresh idle preflight. Preserve profile and reopen normally.

## Not selected for this pass

Snooze adds another sidebar taxonomy to an already compact interface; leave it as a future option. Rich editor, generic/question attachments, model-capacity continuation and generalized inline context records require broader retention/native contracts. Integrated Git-host actions, auto-resume, auto-cleanup and additional providers change authority or execution and are outside the chosen Muse workflow scope. Existing forks, worktrees, queues, compaction, catalogs and bounded renderer delivery are already implemented.

## Acceptance

Each feature has focused offline and preview/Electron evidence, independent task review and a commit. Final review covers combined interactions. CI must pass all required groups at the published SHA; the verified installer must match release manifests, preserve sessions and expose the new controls in the installed artifact. Never infer native provider acceptance from a fixture.
