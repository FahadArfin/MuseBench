# Prompt timeline

Implement the supplied narrow conversation rail in Muse Code and personal chat. Each tick represents a rendered user prompt, in chronological order. Hover or keyboard focus shows a small dark/light matching preview card with the prompt and following assistant excerpt. Clicking or Enter scrolls to that prompt without changing or resending it. The current section has a longer highlighted tick. Arrow keys, Home/End and touch buttons work; Escape dismisses previews. Keep a bounded scrollable rail for long conversations and fit narrow windows.

Use a shared DOM-only timeline module in the existing React UI and official personal browser documents. It observes rendered messages, retains no account data, invokes no network/API or message action, and changes only scroll position. Personal integration is origin/layout guarded, removed in original website mode, and cleaned up on navigation. Muse's known message roles are supported; inspect normal Meta AI's rendered structure before adding a matching adapter. Unsupported/unloaded content must not be invented. Preserve drafts, plan/review gates, login and all sandbox settings.

Validation: failing interaction test first, fictional long chats in real Electron for both surfaces, hover without scroll, exact jump targets, active tracking, repeated prompts, keyboard/touch, streaming, replacement/navigation, teardown, empty chats, theme and narrow layout. Build/package and saved-login read-only verification; no model request is necessary for navigation.

The user confirmed both Muse and regular Meta AI Chat, reported a blocked login, asked for one app-wide sign-in, and noted the light Meta theme. The implemented web-session reuse preserves the existing Muse partition and stored account cookies, admits only the observed auth.meta.ai redirect, and refreshes shared-account metadata on authentication. It cannot combine CLI authentication or remove Meta-required service confirmation. Native theme synchronization covers Meta’s System setting.
