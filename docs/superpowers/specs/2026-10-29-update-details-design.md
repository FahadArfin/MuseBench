# Clear update details and restart impact

Roadmap C07, authorized by the continuing implementation request. Keep the existing green download icon and Settings → Updates as the two entry points. No new modal, automatic download, forced restart or model request.

Settings distinguishes the installed version, published offer and the exact confirmed download. Finished release metadata provides a bounded plain-text What's new disclosure plus a link to that exact GitHub release. Provider HTML is not rendered or executed. An unavailable release summary remains explicit.

When a download is ready, display a compact list of work preventing restart: named Code chats/checks/queued work/goals, Work or Sites requests, dictation, Customize, billing/sign-in and owned app/mobile control activity. Existing update shutdown guards remain authoritative and run again immediately before installation. The list does not stop, cancel or retry any work. Refresh the list while this settings panel is open, and keep the toolbar's version and status consistent.

Release metadata and download identity survive failed downloads, blocked restarts and periodic checks; stale or mismatched download events never enable installation. Read-only snapshots remain bounded and do not copy inactive transcripts. Preview uses the same UI with explicit simulated metadata and never invokes an installer.

Tests cover exact version ownership, bounded inert notes, changing blockers, shutdown races, duplicate admission, preview/desktop rendering and a narrow panel. Final review and a feature commit/push precede exact published/installed acceptance.
