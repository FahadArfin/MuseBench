# Native context usage

The resumed completion audit found that SDK 1.4.14 already exports `session/contextUsage` and snapshot `contextUsage`, although MuseBench currently ignores both. This corrects the blanket claim that context occupancy is not reported. It extends OC06's existing context indicator and Session details; it does not replace the still-open retention/background-summary work.

Show the latest native **reported occupancy floor**, not an exact present-time context size. A native reading consists of usedTokens, optional windowTokens and server-computed pressure. Validate nonnegative safe integers; a usable window is positive. Missing/invalid data is unknown, never zero or a fabricated model limit. Unknown pressure labels remain unknown. Values can legitimately decrease after compaction or exceed the reported window; text retains the reported values and a meter clamps only its visual fill. No thresholds are invented.

Admit live readings through the existing session/cursor validation and connection owner. Restore only from a supported anchored snapshot whose cursor/session has been checked. Inline history without a reading stays unknown. Duplicate/conflicting cursors, old connection callbacks and foreign sessions cannot change the displayed fact. Keep one bounded reading per chat, with observed time and live/restored provenance. Persisted readings are labeled saved/disconnected after restart; reconnecting without a new reading must not promote an old one to current. Delete/recreate and background chat switching retain exact ownership. Reconcile the task row before an older app snapshot after an interrupted write.

Use one compact Context button above the Code composer when a reading or compaction history exists. A reading shows its reported percentage only when its own window is known; otherwise show its token count. Session details show last-reported usage, optional meter, native pressure, freshness and timestamp. Keep opaque IDs in optional details. Existing local prepared-request estimates, usage/billing and compaction history remain distinct. Replace blanket unknown copy with conditional copy. Shared renderer, keyboard/narrow layout and existing motion/accessibility behavior apply.

No native commands, model requests, permission changes, background summaries or new dependencies are required. Native provider acceptance remains separate from injected event/snapshot evidence. SDK latest was independently rechecked as 1.4.14 on 30 October. The native reasoning-effort snapshot/notification is a separate follow-up audit, not part of this correction.

Implementation choice: reuse the verified adapter state projection, a finite shared normalizer/presentation helper, owning controller persistence and the existing Session dialog. Avoid reading raw notifications outside adapter validation or deriving context occupancy from billing totals or compaction before/after snapshots.
