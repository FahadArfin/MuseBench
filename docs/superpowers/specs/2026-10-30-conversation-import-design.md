# Conversation import with preview

CX03 adds an Import chats action to the existing chat library. Users choose a local ChatGPT/Claude conversation JSON export or ZIP, MuseBench's documented portable JSON format, or a Markdown/text transcript. A compact preview shows source format, conversation/message counts, omissions and duplicates; users can search every parsed conversation, inspect text and select what to save. Confirmation stores searchable local history. It never creates or resumes a provider session, sends a message, or imports account data, project instructions, tools or permissions.

Imported conversations appear alongside saved chats in library search, with an Imported label and source provenance. Opening one shows read-only text and a way to stage an excerpt in the currently selected chat's existing draft, preserving attachments/mode and requiring an explicit send. Removing an import removes only the local copy; source files are never changed.

Provider export guides establish export availability, but do not promise a stable JSON schema. Adapters must validate supported shapes and report unsupported formats rather than pretending every export is supported. ChatGPT's selected mapping branch is followed with cycle/missing-parent checks; alternate branches and non-text/system/tool content are reported as omitted. Claude imports human/assistant text blocks, excluding thinking/tool blocks and attachments. Portable format is versioned. Plain text is a document, not guessed speaker roles.

Sources read 30 October: [OpenAI export guide](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data), [Claude export guide](https://support.claude.com/en/articles/9450526-export-your-claude-data). Observed adapter shapes corroborated by the [ClaudeExplorer source project](https://github.com/davehaas/claudeExplorer) and [session-pack adapter design](https://github.com/ohdearquant/khive/blob/main/docs/adr/ADR-080-session-pack-oss-storage-mechanism.md); these are compatibility evidence, not provider guarantees. [yauzl](https://github.com/thejoshwolfe/yauzl) supplies bounded lazy ZIP reads; npm reports version 3.4.0.

Native file selection alone admits filesystem paths. Parse work runs off the main UI thread. A bounded, expiring preview token binds the selected source digest and normalized content; confirmation rechecks the source digest. Only selected records are atomically committed, with persistent content deduplication. A failed or stale confirmation leaves no partial import. Imported records use separate identities from tasks and cannot be passed to native chat navigation/run APIs.

Limits are explicit: 128 MiB selected archive, 32 MiB total decoded conversation JSON/text, 2,000 conversations, 50,000 messages, 1 MiB per message and 16 MiB normalized text. Commit at most 100 conversations/2 MiB text per selection to keep local indexing responsive. Review exposed that byte/count bounds alone admit excessive short-message writes, so confirmations also cap 2,000 messages and 20,000 per-message unique index terms. Oversized individual conversations require a smaller export; no shared SQLite transaction yields to unrelated work. ZIP handling reads only conversation JSON entries, with entry/count/expanded-size limits and per-entry CRC-32 verification; no extraction, external references or executable content. Oversized/invalid input fails with a useful explanation rather than silent truncation. Bounded preview excerpts do not truncate saved text.

Both desktop and browser preview use the same parser and UI. Browser sample data is explicitly labeled; Electron/controller tests exercise real isolated storage and file import without provider calls. Desktop installation remains a separate verified-release step.
