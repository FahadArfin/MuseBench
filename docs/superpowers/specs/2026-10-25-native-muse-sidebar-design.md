# Native Muse sidebar

The user requests real Muse chats, ideas, and goals in a Codex-like native sidebar, preserving the existing app. Keep Electron/React, the current login partitions, and Muse Code. The builder's approach is a native navigation shell driven by bounded metadata from rendered official collection UI. Public documentation consulted does not expose a full consumer listing API. A private API integration would be brittle and unnecessary; a shortcut-only sidebar would not satisfy this request.

Display a native New Muse chat action, local title search, refresh, collapsible Muse chats/Ideas/Goals groups, item selection, and selected title in the header. Keep regular Meta AI Chat and the Muse AI bot entry accessible. Load collection pages in the existing retained service views when the personal workspace becomes visible. Retain the main conversation, and show honest empty/loading/unavailable states. Render at most 100 items per group, initially show a small subset with Show more. Treat these as rendered items, not an exhaustive account export.

The signed-in UI observed on 2026-10-25 exposes a Side chats navigation panel, an inert new draft route /thread/new, idea buttons with data-pel-click=idea_group_row_click and h3 titles, and a Goals page with a Create a goal empty state. Opening an idea displays a preview; execution is a separate Let's do it action. This account currently has no side chats or goals. Future nonempty groups require semantic rendered controls and must fail gracefully if unmatched.

Read only bounded titles and navigation targets from those collection containers. No message bodies, hidden framework state, network interception, private APIs, cookies, tokens, or permissions. Keep the catalog in main-process memory and expose only opaque IDs/title/kind metadata to local React. Local commands select catalog IDs, never arbitrary URLs or selectors. Invalidate stale asynchronous reads and clear metadata on sign-out/auth navigation. Remote content retains no preload, Node, or workspace bridge.

Keep official composition, previews, account, and approval interfaces in the main area; remove redundant navigation when the integrated layout is enabled. Full website layout remains recoverable. Test source, packaged workflows, real signed-in collection metadata/selection, lifecycle races, and coding regressions. Save only counts/booleans in live reports; use fixture data for screenshots.

Real thread pages do not expose the root Side chats panel. Keep the root collection document at `/`, create retained views for validated chat links, and reuse a pending `/thread/new` view without discarding an unsent draft. Closed idea previews have a verified visible-heading marker, allowing native selection to clear and the same row to reopen the preview. Forward finite native sidebar shortcuts from remote contents. Muse-owned authentication popups invalidate metadata and pending reads just like retained-view authentication; separate regular Meta AI login does not clear Muse data.
