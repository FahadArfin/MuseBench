# Reviewed on-demand tools

Open **Muse connection**, choose **Interactive · Full access**, and expand **On-demand tools**. Select up to four sources, review their exact executable/folder or remote endpoint/header names and referenced environment names, then explicitly allow their execution for this connection. Opening or refreshing the list, selecting a row and checking review make no source connections. Default selection is empty.

This path supports already-reviewed global stdio and remote HTTP definitions that are explicitly disabled for direct native loading. Use the existing Customize Review and Disable controls first. An old definition review establishes provenance; it is not permission to execute a disabled definition. Execution consent is consumed once, stays in memory, and must be given again on reconnect.

Bare native executable names such as `node` are bound to their resolved absolute path, executable identity, reviewed configuration and effective PATH. A changed resolution requires fresh review. Absent or `auto` framing attempts the bounded JSONL MCP initialization handshake. Explicit content-length framing, Windows command scripts such as `npx.cmd`, project overlays and plugin source wrapping remain on their existing direct path. MuseBench does not rewrite commands or edit source configuration. Known unrelated plugin capabilities and skills/hooks-only plugins do not prevent discovery; colliding or uninspectable plugin MCP declarations are shown explicitly.

`discovery_search` starts admitted sources lazily and returns their tool schemas as untrusted data. It returns at most eight matches across the selection. This is a fixed native gateway, not native deferred schema registration. `discovery_call` invokes exactly one admitted source/tool using its current catalog revision. Native Ask me approval remains authoritative. Calls may have arbitrary external effects; the gateway is not read-only, idempotent or sandboxed. Sampling, elicitation and task creation are not forwarded.

An approval for the exact app-owned discovery call shows compact **Source** and **Tool** rows when its request matches the current runtime session/turn and its source ID is in that connection's reviewed selection. Source is the reviewed ID; tool names render literally. The existing complete raw wrapper, request and arguments remain below, with keyboard access to scrolling details. These rows identify what was requested; the catalog digest does not certify freshness, safety or provider authorization. The gateway still checks source/catalog/tool before execution. Unresolvable or stale attribution uses the generic raw view. One-time approval/denial tokens and incomplete-detail approval blocking stay unchanged.

Catalogs are limited to 200 tools and 512 KiB per source. Individual schemas are limited to 32 KiB and depth 16; unsupported validation keywords and structures are excluded and counted. The local validator supports type, object properties/required/additionalProperties, homogeneous arrays, length/item/numeric bounds, enum/const, and bounded allOf/anyOf/oneOf. It does not resolve references, apply formats or regular expressions, insert defaults, coerce inputs, or load remote code. Validation runs in an owned worker outside Electron's main loop.

Search responses are at most 64 KiB, call arguments 64 KiB and call responses 128 KiB, including encoded envelopes. A completed oversized result returns a source/tool receipt with explicit truncation. Each operation has a 4 MiB process-output budget and 64 KiB stderr budget. Source startup/catalog reads take at most 30 seconds and tool calls at most 300 seconds. Queue, frame, broker and output-drain bounds also apply. A healthy idle connection has no age limit: its owning pipes and Windows Jobs determine lifetime, with bounded cleanup when the owner closes.

A submitted call is never retried automatically. A timeout, cancellation, source EOF or lost receipt can leave an **unknown** outcome; the operation may have executed. Inspect effects before deciding what to do next. Its source transport closes and cannot restart within that selection. Native disconnect closes the broker-owned worker and its child/grandchild process trees; an unconfirmed cleanup blocks replacement connections and app restart.

Saved sessions retain only source identities and revisions in MuseBench. Reconnecting requires the exact selection and fresh review. Unsupported saved selections retain the native conversation identity in recovery. To change sources or abandon an unsupported configuration, use **Session → Start fresh session** explicitly; local conversation history and project files remain available.


Remote discovery uses a separate pinned MCP client 2.4.0 and supports current 2026-07-28 peers, older Streamable HTTP JSON/POST SSE, and historical same-origin SSE endpoints after a definitive pre-call HTTP 404/405 transport incompatibility. Existing `streamable-http`, `http` and `streamable_http` aliases retain their configuration meaning. The local/native SDK pins remain unchanged. Signed-in sources use a token-only provider with no unauthorized handler; no optional input-fulfillment handler is installed; current input-required and task results never trigger automatic continuation.

Remote headers can contain configured private values or use Muse's established `${VAR}`, `${VAR:-default}` and `$$` expansion in URLs/header values. Missing variables, malformed or unsupported input expressions, and invalid expanded settings are visible incompatibilities. Defaults apply when a referenced variable is unset or empty; bare empty variables remain empty. Escaped dollars and substituted environment values are literal output and are never rescanned as expressions. Exact raw and resolved settings bind the source revision; changing an environment token invalidates consent. Header values remain private. A variable URL displays its original template and the resolved network origin, without displaying substituted private path segments. Only referenced variable names enter the shared review.

HTTPS is required except explicit loopback HTTP. User information, query, fragment, contradictory execution fields, duplicate or transport-owned headers are rejected. Header maps have at most 32 entries, 4 KiB per value and 8 KiB encoded total; expansion is limited to 16 KiB per setting. Requests refuse all redirects and validate/pin DNS destinations on every connection: public hostnames cannot resolve to loopback/private/link-local addresses. Explicit private literal HTTPS destinations retain source-bound consent. This Node network boundary uses no ambient proxy, cookie jar or unsafe TLS setting.

Remote transport bounds before parsing: 16 KiB response headers, 4 MiB compressed wire bytes per response, 2 MiB decompressed body, 1 MiB incomplete SSE frame (including comments), 4 MiB aggregate operation bytes, and a separate 16 MiB background-stream lifetime budget. The smaller catalog/search/argument/receipt limits still apply. Startup negotiation shares one total startup deadline. A 401/403 requires explicit authorization setup; no browser opens, auth refresh, scope escalation, stream reconnect, session reinitialization or effect replay occurs. Historical EventSource EOF/errors close its reader and reconnect timer. Session IDs remain private in memory; optional DELETE cleanup has a separate 500 ms deadline and accepts 405. Disconnect confirms local ownership/socket cleanup, never cancellation of an already-submitted remote effect.

For a remote source without a configured Authorization header, use its inline **Prepare sign-in** controls. Review the endpoint before bounded metadata discovery; review any new metadata origin and the advertised issuer before reading them. Review scopes, resource, issuer, callback and public-client method before **Begin sign-in** opens your system browser. Dynamic registration is a remote write and is stated before Begin. A provider without usable registration needs an approved native public client ID and loopback callback port; **Set up public client** accepts those two public values only. Never enter a client secret. Confidential clients and DPoP are unsupported. Check status reads local state only.

Successful sign-in says **Signed in on this device**. It clears execution selection: select and review the source again, then explicitly Connect. No sign-in action connects Muse, searches tools or sends a model prompt. New enrollment changes the saved source identity; resuming a session with an older enrollment requires explicit recovery. An unchanged global enrollment can be reused in another project after fresh source review; changes to profile/global settings location, source ID, endpoint, header templates/values or authentication policy need a matching new enrollment. Project/root/plugin overlays still invalidate execution consent.

Access and refresh tokens stay in the app's encrypted local grant ledger, protected by real asynchronous OS credential protection. There is no plaintext fallback. A protected unreadable or unknown ledger is preserved. Refresh happens only before connection or before starting native work, with source dispatch held idle; it never follows an unauthorized tool response. Refresh intent is saved before one refresh POST; a lost result needs sign-in again. **Retry saving** saves the held result without repeating the exchange. Token rotation preserves the enrollment marker. Opening a different chat cancels a pending interactive sign-in while unchanged background runtime leases retain their own authority. Actual close/root/epoch/source/account replacement revokes them.

**Forget local sign-in** removes this app's saved enrollment after owned source cleanup. It does not revoke the provider grant, delete a dynamic registration, log out the native CLI, or sign out your browser. Active work prevents account changes. MuseBench does not read native Muse OAuth storage or claim compatibility with personal providers from scripted fixtures. Direct native authentication remains separate.


Signed-in sources show a compact status and the approved scopes. **Sign-in details**, **Sign in again** and **Review local Forget** disclose the respective local review; discovery, provider details and local deletion have separate checkboxes. Missing scope information is not labelled as no scopes.

A known refresh result whose protected write fails remains available for bounded local **Retry saving**. Ordinary failed connection cleanup revokes execution and leaves only that save capability for the same selected chat/folder/epoch. Saving repeats no token exchange or request. Review execution freshly before reconnecting. An idle connected session can Check status, Cancel or Retry saving without disconnecting; source execution and account changes remain locked. Active work keeps those controls disabled. Explicit disconnect, changed owner/source/enrollment or expiry invalidates stale recovery and may require sign-in again.

## Useful oversized result previews, 30 October 2026

After the complete received result and any advertised structured output schema pass validation, oversized calls retain a lossy text preview. The source ID/name, catalog revision, tool and completed/failed outcome remain attached. Small results retain their complete original result shape, including source-provided fields.

The preview concatenates MCP text content in source order and keeps a balanced beginning/end with an omission marker, up to 16,000 Unicode code points including that marker. Astral characters remain whole; combining marks count separately rather than as grapheme clusters. `preview.omittedTextCodePoints` counts omitted source text code points, while `preview.originalWireBytes` measures the complete original nested JSON-RPC frame in bytes using the maximum encoded size of any admitted request ID (128 UTF-16 code units at up to six JSON bytes per unit, plus quotes) and the emitted JSONL delimiter. This is a conservative frame size, not an observed network byte count. The gateway shrinks text further when needed to keep the fully encoded preview response at or below 131,072 bytes.

Preview output has `truncated:true`, `preview` and an explicit loss notice instead of `result`; it is never a partial authoritative `structuredContent`. Images, audio, resource blocks, arbitrary metadata and structured output are omitted. `preview.omittedNonTextBlocks` counts omitted content blocks. Structured-only or media-only output explains that no text is available. If the original result itself has `truncated:true`, the notice explicitly attributes that separate truncation to the source. A source `isError` result remains a failed outcome. Invalid original output remains unknown and closes its transport without replay, even if its text could have been previewed.

See [CS02 validation](validation/2026-10-30-discovery-output.md) for disposable fixture and frame-boundary evidence. Transport receive limits and once-only submission behavior are unchanged.
